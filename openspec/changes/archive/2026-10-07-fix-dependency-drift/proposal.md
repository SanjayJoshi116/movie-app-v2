## Why

The backend runs a different Django in each place:
- Docker runs **Django 4.2**, because `backend/requirements.txt` says `django>=4.2,<5.0`.
- Development and the test suite run **5.2.17** (the `django` Anaconda env).
- Several migrations were generated by **6.0.x**: base Anaconda has Django 6.0.3 installed, and `manage.py` was run with the wrong interpreter.

Every other Python dependency is an open `>=` range, so a fresh install or Docker build can pick up versions nobody has tested. The frontend is fine: `package-lock.json` is committed and in sync, and `Dockerfile.frontend` uses `npm ci`. Two other gaps:
- The Docker base images lag the toolchain the app is tested on: `python:3.11` against dev's 3.12, and `node:18`, which is end-of-life.
- A few docs still describe the Express proxy removed in 0.15.4.

This is part of backlog item 7 (CI gaps, drift and polish), split into focused changes. This one covers dependency and version drift.

## What Changes

- **Backend dependencies are pinned to the versions the tests run on.**
  - `requirements.txt` targets **Django 5.2 LTS** and pins each direct dependency to its tested version.
  - A generated `backend/constraints.txt` pins every transitive dependency too.
  - `requirements-test.txt` and `e2e/python/requirements.txt` are pinned the same way. The Python Playwright version matches the npm `@playwright/test` version (1.60.0).
- **Docker builds use the pinned set:** `pip install -r requirements.txt -c constraints.txt`.
  - The Python base image moves to `python:3.12-slim`, matching dev.
  - The frontend build image moves from `node:18-alpine` to a current LTS image.
- **Guard against running the wrong Django.** A backend test fails when the installed Django's major.minor doesn't match `requirements.txt`. It catches the "ran with base Anaconda's Django 6.0" mistake at test time.
- **Migration headers stay as they are.** The "Generated by Django 6.0" comments are misleading but harmless. Editing applied migrations only adds noise (see design.md).
- **Stale Express references are removed:**
  - `docs/ARCHITECTURE.md`: the avatar-URL bullet's reasoning, the `server.js` multipart bullet (it describes deleted code), and the API-key bullet
  - the `e2e/python/conftest.py` docstring

  The backlog also named `.env.docker` and `.env.example`, but neither mentions Express any more, so those two are dropped.

## Capabilities

### New Capabilities
None.

### Modified Capabilities
None. This is build tooling and docs only, so `.openspec.yaml` sets `skip_specs: true`.

## Impact

- **Files:**
  - `backend/requirements.txt`, `backend/requirements-test.txt`, new `backend/constraints.txt`
  - `e2e/python/requirements.txt`
  - `backend/Dockerfile`, `Dockerfile.frontend`
  - `docs/ARCHITECTURE.md`, `e2e/python/conftest.py`
  - a new test in `backend/userdata/tests/`
  - `README.md` and `CLAUDE.md`, a short note on regenerating the constraints file
- **Deploy:** the production Docker image moves from Django 4.2 to 5.2. That's a real runtime upgrade for Docker deployments, but it's the version every test already runs on. There are no new migrations.
- **Overlap:** `harden-docker` (proposed in parallel) also edits both Dockerfiles. The edits here are limited to the `FROM` lines and the pip install line, so the two merge trivially.
- **Not covered here:** CI steps and the CI Node version (`ci-coverage`), and the Docker security items (`harden-docker`).
