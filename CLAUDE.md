# CLAUDE.md

Guidance for Claude Code when working in this repo. See `README.md` for feature/architecture docs and `docs/ARCHITECTURE.md` for detailed design-decision rationale (auth, pagination, responsive breakpoints, recommendations caching, etc.) — this file covers conventions not obvious from reading the code once.

## Stack
- Frontend: React 18 + TypeScript (strict) + Ant Design 5, CRA (`react-scripts`), React Router v6, Framer Motion, Recharts.
- Backend: Django 4 + DRF + PostgreSQL, JWT auth (`djangorestframework-simplejwt`).
- `npm run dev` starts both: React dev server (3000), Django (8000). Django runs via the Anaconda env: `G:/Anaconda/envs/django/python.exe` (see `package.json` scripts) — use that interpreter for any manual `manage.py` command, not system Python. `predev`/`prestart` run `kill-port 3000 8000` first so a stale process from a previous run doesn't silently block startup. `backend/start.py`'s pre-startup steps run in order — DB create → migrate → best-effort `compute_recommendations` (capped at 30s, `subprocess.TimeoutExpired` caught and skipped) → `runserver`. That timeout matters: without it, a slow/hung TMDB call during the cache-warm step blocks `runserver` from ever starting, and `npm run dev` just never finishes booting Django with no error surfaced.
- TMDB requests are proxied by Django itself (`backend/userdata/tmdb_proxy_views.py`'s `tmdb_proxy`, mounted at `api/tmdb/<path:tmdb_path>`, `AllowAny` since it's public data) — there is no separate Node/Express layer (removed in 0.15.4). It uses a shared module-level `requests.Session()` with retry/pooling (`HTTPAdapter`+`Retry`), not a bare per-call `requests.get()` — a movie/TV detail page fires ~6 concurrent proxy calls, and a fresh-handshake-per-call approach saw sporadic transient 502s under that burst.

## Conventions to reuse, don't reinvent
- **Font size**: never hardcode `fontSize: N`. Import `FONT_SIZE` from `src/constants/typography.ts` (`caption` 12 / `body` 14 / `emphasis` 16 / `display` 28). Icon-scaling `fontSize` props (antd icons) are the one exception — those stay numeric.
- **Info tooltips**: use `<InfoTooltip title="..." />` from `src/components/InfoTooltip.tsx` (wraps antd `Tooltip` + `InfoCircleOutlined`) next to any label/stat that needs a one-line explanation. Don't hand-roll a new `Tooltip`+icon pairing.
- **Dates**: render with `formatDateDMY()` from `src/utils/formatDate.ts` — fixed `dd-mm-yyyy`, not locale-dependent `toLocaleDateString()`.
- **Fonts**: Poppins is set once via `commonTokens.fontFamily` in `src/theme/antdTheme.ts`. Never add a per-component `fontFamily` override.
- **Detail-page sections**: `MovieDetails.tsx` and `TVShowDetails.tsx` share `SectionHeader` (section divider+title), `WatchProviders` (streaming/rent logos), `MediaCardGrid` (poster-card grid for recommendations/similar/credits, default `limit=20`, optional `title`/per-item `subtitle`), and `ReviewsSection` (2-column review cards) from `src/components/`. Both pages render sections in the same order (Where to Watch → Cast → Recommendations → Similar → Trailers → Images → Reviews). Don't re-inline a copy in one of the two detail components — fix/extend the shared one. `PersonPage.tsx` also reuses `MediaCardGrid` (uncapped, `limit={array.length}`) for its Movies/TV credit tabs instead of a local card component. Both Recommendations and Similar are additionally run through `filterByGenreOverlap()` (`src/utils/filterByGenreOverlap.ts`) before being handed to `MediaCardGrid` — keeps only items sharing ≥half the opened title's genres, falls back to the unfiltered list rather than showing nothing. Reuse this util for any new genre-filtered grid instead of writing another overlap check.
- **Nav icon tooltips**: `Sidebar.tsx` and `BottomNav.tsx` both use `useFlashTooltip()` (`src/hooks/useFlashTooltip.ts`) to force-show a nav icon's `Tooltip` for ~1.4s right after it's clicked (`open={flashKey === key || undefined}`), since the tablet icon-rail and phone bottom-nav have no visible text label to confirm the destination. Reuse this hook for any new icon-only nav control instead of a bespoke timeout/state pair.
- **Library item cards**: `WatchlistPage.tsx`, `WatchedPage.tsx`, and `ListsPage.tsx` share `LibraryItemCard.tsx` (poster + `Card.Meta` + icon action buttons) for their item grids. `PeoplePage.tsx` and `SearchPage.tsx`'s People tab share `PersonCard.tsx`. Don't hand-roll another `Card`/`Row`/`Col` poster grid — extend one of these. `LibraryItemCard.tsx`'s outer `motion.div` needs `height: "100%"` for cards in the same grid row to render equal height (antd's `Col` stretches to the row's tallest sibling by default, but only the wrapper explicitly filling that height makes the visible card box follow) — don't drop it when touching this component.
- **Watched status source of truth**: there is exactly one "is this watched" boolean per title — the shared `WatchedContext` (`isWatched(id, type)` / `toggleWatched(...)`). `WatchlistEntry` has no `watched` column; don't add one back or otherwise let a page maintain its own separate watched flag — it will drift out of sync with whatever else marks/unmarks the same title.
- **Shared UI constants**: `IMG_URL`, `BACKDROP_URL`, `RATING_GOLD`, `WATCHED_GREEN` live in `src/constants/ui.ts`; provider deep-links (`PROVIDER_SEARCH_URLS`) live in `src/constants/providers.ts`. Don't hardcode hex colors or TMDB image URLs inline — for one-off section-header/divider colors, prefer antd's `theme.useToken()` (e.g. `colorTextSecondary`, `colorBorderSecondary`, `colorError`) over a literal hex, per `ProfileModal.tsx`.
- **No-poster fallback**: use `<PosterPlaceholder className="..." style={{...}} />` (`src/components/PosterPlaceholder.tsx`) wherever a poster/profile image might be missing — pass the same className the real `<img>` would use (`movie-poster-img`, `rec-card-img`, `cast-card-img-lg`, `detail-poster-img`) so it picks up the same aspect-ratio/border-radius. It's a real DOM element (renders "No Image" text that inherits the app's Poppins font), not an image — don't reintroduce an SVG-data-URI placeholder (`NO_IMAGE` was removed for exactly this reason: text baked into an `<img src="data:...">` SVG can't see the page's `@font-face`, so it could never match the rest of the UI's font). Two call sites (`PersonPage.tsx`, `StatsPage.tsx`) pass an extra `style={{ aspectRatio: "2 / 3" }}` since their real-`<img>` counterpart has no CSS class enforcing one — check whether yours needs the same before assuming the className alone sizes it.
- **Light/dark theme parity**: `src/theme/antdTheme.ts`'s `darkThemeConfig` and `lightThemeConfig` should carry the same token set (`colorText`, `colorTextSecondary`, `colorBorder`, `colorBorderSecondary`, `colorBgElevated`, plus `Table`/`Drawer` component overrides) — light mode used to only override 3 background tokens and fell back to stock antd gray for everything else, which is why it looked unfinished next to dark mode's bespoke "cinema-dark" palette until this was fixed. If you add a new token/component override to one theme, add the equivalent to the other. Same for `App.css`'s `body.dark-theme`/`body:not(.dark-theme)` scoped rules (`.app-content` gradient, `.glass-sidebar`, `.glass-overlay-card`, `.app-bottom-nav`, `::-webkit-scrollbar-*`) — every rule scoped to one theme needs its sibling, per the scrollbar bug this fixed (it was unscoped entirely, so it stayed dark-navy even in light mode).
- **Avatar URLs**: a user's `avatar_url` (from `AuthContext`'s `user` object) is a relative Django media path — always resolve it through `resolveAvatarUrl()` from `src/constants/media.ts` before passing to an `<Avatar src=... />`; never concatenate `REACT_APP_API_BASE_URL`/TMDB constants with it. Uploading/removing a photo goes through `uploadAvatar()`/`removeAvatar()` (`src/api/userApi.ts`) then `setUserData()` (`AuthContext`) to push the returned user into context/localStorage — the same helper `updateProfile()` uses internally, so don't duplicate the persist-to-localStorage logic inline.
- **List-page filter bars**: `WatchlistPage.tsx`/`WatchedPage.tsx` share the pattern via `useLibraryFilters` (`src/hooks/useLibraryFilters.ts`) + `MediaGrid` (`src/components/MediaGrid.tsx`) — `keyPrefix` param must stay `"watchlist"`/`"watched"` (matches each page's pre-existing sessionStorage key names) and an optional `extraFilter` predicate lets a page layer one more filter on top (Watchlist's watched-status filter) without forking the hook. `RecommendationsPage.tsx`, `ListsPage.tsx`, `ListDetailPage.tsx`, and `FollowingPage.tsx` still each hand-roll the same shape locally (`search`/`sortKey`/`typeFilter` state + `SS_*` sessionStorage constants + `Input.Search`/`Select` bar + conditional "Clear filters" button) — reuse `useLibraryFilters`/`MediaGrid` for any new list/browse page filter instead of hand-rolling another copy, and consider migrating these four onto it too next time one of them needs a real touch.
- **Adult content toggle**: single switch lives in `FilterPanel.tsx`, bound to the shared `includeAdult`/`setIncludeAdult` from `useAppContext()`/`UIContext`. Don't add another copy elsewhere (e.g. back into `SearchBox.tsx`) — every search/discover call already reads this one context value.
- **Add to List**: use `<AddToListModal open onClose mediaId mediaType title posterPath voteAverage />` (`src/components/AddToListModal.tsx`) — don't re-inline another bare-checkbox list picker. It already handles search, inline create-new-list, and the add/remove toggle itself.
- **Mark as Watched**: use `<MarkWatchedModal open mediaId mediaType onCancel onConfirm />` (`src/components/MarkWatchedModal.tsx`) whenever a UI lets the user mark something watched — it self-fetches runtime + streaming-platform options from TMDB given just the id/type, so callers never pass detail data in. Only wire it for the "mark as watched" direction; unmarking stays an instant `toggleWatched(...)` call, no modal. If you add a new watched-toggle icon anywhere, route it through this modal — several existing ones (`Movie.tsx`, `TVShowCard.tsx`, `RecommendationsPage.tsx`, `SearchPage.tsx`, `WatchlistPage.tsx`) were missed on a first pass and silently never recorded runtime/platform until fixed.
- **Search inputs**: every page-level search/filter `Input`/`Input.Search` needs explicit `id`, `name`, and `autoComplete="off"` — Chrome DevTools flags free-text inputs missing these. Follow the existing ones (`WatchlistPage.tsx`, `WatchedPage.tsx`, `PeoplePage.tsx`, `SearchBox.tsx`, etc.) for naming (`"<page>-search"`).
- **Login/register API calls**: use `publicApi` from `src/api/userApi.ts`, not the default `userApi` export. `userApi` carries a 401-refresh interceptor that, on a failed login, finds no refresh token yet and hard-redirects to `/login` — before the page's own error handling can show a message. `publicApi` is the same base client with no interceptors, meant exactly for login/register/password-reset.
- **Responsive breakpoints**: three CSS-only tiers, no JS width checks (`Grid.useBreakpoint()`, `window.innerWidth`, etc.) anywhere in the app — keep it that way. `<768px` phone (`Sidebar` hidden, `BottomNav` shown), `768-991px` tablet (`Sidebar` collapses to a 64px icon rail via `App.css`'s `@media (min-width: 768px) and (max-width: 991px)` block), `≥992px` desktop (full 220px sidebar, the unqualified default). New fixed-width elements (modals, cards, filter inputs) should use `width: "100%", maxWidth: N` instead of a bare `width: N`, per the auth-page `Card`s and list-page filter bars — a bare fixed px width is exactly the pattern that overflows on phones under that width.
- **Sidebar manual collapse (desktop only)**: `Sidebar.tsx` also lets the user fold the full 220px sidebar down to the same 64px icon rail tablet gets automatically, via a footer toggle button. State is `collapsed` (`useLocalStorage<boolean>("cinedb_sidebar_collapsed", false)`, same hook/key-prefix convention as `cinedb_theme`), applied as a `.sidebar-collapsed` class on `.app-sidebar`. The collapsed-state rules live in `App.css`'s `@media (min-width: 992px)` block and intentionally re-target the same child selectors (`.sidebar-logo-full`, `.sidebar-label`, `.ant-menu-item` padding, etc.) as the tablet rail — don't fork a second set of rules. The toggle button itself (`.sidebar-collapse-toggle`) is hidden below 992px since tablet/phone already have their own fixed layout.
- **Sidebar vertical space budget**: `.app-sidebar` is `height: 100vh; overflow-y: auto` — a deliberate safety valve, not a bug — but it's already flush with zero slack at a standard 1366×768 viewport. `Sidebar.tsx` renders one extra element (the filter-toggle button) only when `isBrowsePage` (`/movies`, `/tv`, `/anime`), so those three routes have less headroom than every other page. Don't add new always-or-conditionally-rendered elements to the sidebar (logo, search, menu, footer) without checking `scrollHeight` vs `clientHeight` at 1366×768 first — it doesn't take much to tip it into showing its own scrollbar. `NotificationBell.tsx` follows this: it's rendered inline inside the existing theme/collapse-toggle footer row, not as a new stacked row — do the same for any future icon-only nav addition.
- **`usePaginatedFetch`'s `restoredState` param and its StrictMode trap**: the hook (`src/hooks/usePaginatedFetch.ts`) supports two restore modes — refetch `restore.savedLoadedPages` pages over the network (Home/Anime/People, restore info comes from router `location.state`), or seed `items`/`hasMore` directly via `restoredState` with zero network calls (Search, which caches full result arrays in sessionStorage itself). Its mount effect guards against React 18 StrictMode's dev-only double-invoke by tracking the last-consumed `fetchPage` reference and no-op'ing a replay with an identical reference — a *real* rerun only ever happens when `fetchPage`'s identity actually changes. Don't remove that guard: without it, the dev-only replay silently re-fetches and clobbers a correctly-restored multi-page/scroll state down to a fresh page 1 (only reproduces under `npm run dev`'s StrictMode, invisible in production builds — found via the app's own documented Playwright verification method, not by reading the code). Relatedly: any `fetchPage`/similar callback passed into this hook must not depend on a non-memoized inline closure (e.g. a `fetcher` prop recreated every render) in its own `useCallback` deps — that reintroduces an infinite refetch loop (`SearchPage.tsx`'s `usePaginatedSearch` hit this; fixed by reading the closure through a ref instead).
- **Per-endpoint throttle scopes**: `LoginThrottle`/`RegisterThrottle`/`PasswordResetThrottle` (`auth_views.py`) established the pattern — subclass `AnonRateThrottle` (or `UserRateThrottle`, for endpoints authenticated users hit too) with a `scope` attribute, register the rate in `settings.py`'s `REST_FRAMEWORK.DEFAULT_THROTTLE_RATES`, apply via `@throttle_classes([...])`. `TmdbProxyThrottle` (`tmdb_proxy_views.py`, `120/min`) and `NotificationsThrottle` (`notifications_views.py`, `30/min`) extend this to the two TMDB-cost endpoints — use `UserRateThrottle` as the base for anything `AllowAny`-or-authenticated that costs real TMDB quota per call, not `AnonRateThrottle` (which no-ops entirely for authenticated requests, per DRF's own `get_cache_key`).
- **Bare `except Exception:` convention**: narrow to what the try block can actually raise — `(requests.RequestException, ValueError)` for a TMDB fetch alone, add `KeyError`/`TypeError` if the code does direct dict indexing (`c["id"]`) instead of `.get()`, add `django.db.Error` if a DB write follows. A handful of sites are legitimately broad on purpose (`recommendations.py`'s `_refresh_cache` and the `f.result()` loop in `_compute_personalized`, `compute_recommendations.py`'s per-user batch loop, `auth_views.py`'s `send_mail` call) — each has a comment explaining why (heterogeneous TMDB+numpy/sklearn+DB operation mix in a background/batch context, or a mail backend whose exception type varies by deploy). Match that judgment for new code — reflexive bare-except is the default to avoid, not broad-catch itself.
- **Token refresh uses a custom view, not simplejwt's stock one**: `urls.py`'s `auth/token/refresh/` route is wired to `SafeTokenRefreshView` (`auth_views.py`), which wraps `TokenRefreshSerializer.validate()`'s unguarded `User.objects.get(...)` and converts a since-deleted token owner into a clean `InvalidToken` (401) instead of an unhandled 500. Don't swap this back to `rest_framework_simplejwt.views.TokenRefreshView` — that regresses a confirmed, reproduced bug (verified via a direct `APIRequestFactory` repro: delete a user, replay their still-unexpired refresh token, stock view 500s / this view 401s cleanly).
- **`ALLOWED_HOSTS` wildcards under `DEBUG`**: `settings.py` appends `"*"` to `ALLOWED_HOSTS` when `DEBUG` is true, mirroring `CORS_ALLOW_ALL_ORIGINS`. This matters because the frontend now calls Django directly (no Express layer in between since 0.15.4) — a LAN device hitting the dev server by IP (`192.168.x.x:8000`) sends that IP as its real Host header, and without the wildcard Django 400s with `DisallowedHost` before the view ever runs. Prod (`DEBUG=False`) stays fail-closed on the `ALLOWED_HOSTS` env var, unaffected.

## Verification
- Typecheck: `npx tsc --noEmit` (fast, always run after TSX/TS edits).
- To actually see a change: `npm run dev`, then drive it with Playwright (`playwright-core` is already a devDependency) — most pages require an authenticated user. Fastest path: register a throwaway account via `/register` (no email verification), then navigate. Movie ID `550` (Fight Club) is a reliable TMDB id for detail-page checks.
- Write any verification scripts into the project root as `verify_*.js` (or `verify_*.py` for E2E/Playwright debugging) and delete them before finishing — don't leave scratch scripts in the tree (`.gitignore` also excludes both patterns as a backstop).
- `useLocalStorage` (`src/hooks/useLocalStorage.ts`) `JSON.parse`s whatever it reads back out of a key, so a script/console write must be JSON-encoded (`localStorage.setItem("cinedb_theme", JSON.stringify("light"))`) — writing the bare string (`"light"` unquoted) makes the parse throw and silently falls back to the hook's default, with no visible error. Bit a Playwright screenshot script that tried to force light theme this way; theme never actually changed until the write was JSON-encoded.
- When scripting a page that renders `SkeletonCard` (`src/components/SkeletonCard.tsx`, antd `Skeleton`/`Skeleton.Image`) while its own data fetch is in flight, don't wait on `<img>` completeness alone before screenshotting/asserting — the real `<img>` tags for its cards don't exist in the DOM yet, so that wait trivially passes on the loading state itself. Wait for `.ant-skeleton` to be gone first, then wait on images.
- `CalendarPage`'s "next 7 days" list is a live TMDB fetch and can transiently come back empty under back-to-back automated requests (e.g. a screenshot script hitting several pages in quick succession), even seconds after the same account got a full list — don't treat one empty result as ground truth in a script/test; retry a couple of times before concluding the range genuinely has nothing.
- `e2e/python/pytest.ini` sets `timeout_method = thread`, not pytest-timeout's default `signal` — required for this suite specifically. A hung Playwright sync-API call blocks in a background thread (its own asyncio subprocess reaper), and `signal`-mode timeouts only interrupt the main thread, so they can't unblock it; the process then rides GitHub Actions' 6h default job timeout instead of failing the one test. `thread` mode force-exits the interpreter on timeout instead, which is Playwright's own documented recommendation. Don't revert this to `signal` even though it means a genuinely stuck test kills the whole run rather than just failing — that's the safer failure mode here. `.github/workflows/ci.yml`'s `e2e-python` job also caps at `timeout-minutes: 15` as a backstop.
- E2E `page.route()` overrides for `/api/(watchlist|watched|ratings|lists)/` need a trailing `**`, not an exact path — `fetchAllPages()` (`src/utils/fetchAllPages.ts`) always appends `?page=1`, even to the first request, so an exact-match pattern silently never fires and the request falls through to whatever broader mock is registered (see `mock_base_django_routes` in `e2e/python/conftest.py`). This isn't just a Python-suite thing — 3 of the 4 TS `*.spec.ts` files had this exact bug independently (missing trailing `**`), undetected until a full suite run. When a test registers more than one route on the *same* pattern to model different requests (e.g. GET the list vs POST to create), don't stack two separate `page.route()` calls — Playwright checks routes last-registered-first, so the second call would shadow the first for every request on that path, not just the one it's meant for. Branch on `r.request.method` inside a single handler instead (see `test_lists.py`'s `test_create_list_success_shows_new_card` for the pattern).
- **Any endpoint an authenticated page calls unconditionally (not just per-feature) must be mocked in every e2e base fixture, or it silently breaks every authenticated test.** `NotificationBell`/`useNotifications` polls `/api/notifications/new-releases/` on mount whenever `isAuthenticated` (it's rendered globally in `Sidebar.tsx`/`BottomNav.tsx`) — when this endpoint shipped, it wasn't added to `mock_base_django_routes` (Python) or any TS spec's `beforeEach`, so the unmocked call 401'd against a real backend and the app's refresh-interceptor redirected every authenticated test to `/login`. The fix is mechanical (one more `page.route()` line per fixture) but easy to miss because the failure symptom (`navigated to /login`, element not found) gives no hint that the *cause* is an unrelated new endpoint — check for this class of bug first whenever a batch of previously-passing e2e tests all start failing with an unexplained login redirect.

## Don't
- Don't inline new "why we did it this way" design-rationale writeups back into `README.md`'s Architecture Overview — that's what `docs/ARCHITECTURE.md` is for (the ~55-bullet "Key design decisions" list used to live in the README until it was moved out for length; README now just links to it). Add new rationale bullets to `docs/ARCHITECTURE.md`, keep README to structure/diagram/feature-level docs.
- Don't bypass `docker-entrypoint.sh` / `backend/start.py` migration flow — `makemigrations` is intentionally not run automatically at boot; generate migrations explicitly.
- Don't add a new localStorage-backed data store — all user data (watchlist/watched/ratings/lists/etc.) lives in PostgreSQL via the Django API.
- Don't add `overflow-x: hidden` (or any non-`visible` overflow value) to `body`/`#root`/any ancestor of `.app-sidebar` without also setting `overflow-y` explicitly — an unpaired `overflow-x` silently promotes `overflow-y` to `auto` too (CSS spec), which turns that ancestor into an unintended scroll container and breaks the sidebar's `position: sticky` (it sticks relative to the nearest scrolling ancestor, not necessarily the viewport). `src/index.css` scopes it to `html` only for this reason.
- Don't let a new dropdown/popover/tooltip anchored inside the sidebar default to antd's `document.body` popup container — set `getPopupContainer` to mount it inside the sticky sidebar instead (see `SearchBox.tsx`), otherwise its scroll-linked reposition logic (built for triggers that scroll with the page) glitches against a trigger that doesn't.
