# CLAUDE.md

Guidance for Claude Code when working in this repo. See `README.md` for feature/architecture docs and `docs/ARCHITECTURE.md` for detailed design-decision rationale (auth, pagination, responsive breakpoints, recommendations caching, etc.) — this file covers conventions not obvious from reading the code once. Known open bugs live in `docs/BUG_BACKLOG.md`, grouped into planned OpenSpec changes. Check it before re-auditing, and keep its status table current when a change is proposed or archived.

## Stack
- Frontend: React 18 + TypeScript (strict) + Ant Design 5, CRA (`react-scripts`), React Router v6, Framer Motion, Recharts. Node 22 (`.nvmrc`, `engines`), the same as CI and `Dockerfile.frontend`. A newer local Node only warns (no `engine-strict`).
- Backend: Django 5.2 LTS + DRF + PostgreSQL, JWT auth (`djangorestframework-simplejwt`).
- `npm run dev` starts both: React dev server (3000), Django (8000). Django runs from a dedicated Conda env: `package.json`'s scripts start it through `scripts/run-django.js`, which takes the interpreter from `DJANGO_PYTHON` (shell, then the untracked root `.env`, else `python`). Never put a machine path back into `package.json`. Use that same interpreter for any manual `manage.py` command, not system Python or base Conda. Base Conda has Django 6.0, which is how some migrations got "Generated by Django 6.0" headers. Backend deps are pinned (`backend/requirements.txt` direct, generated `backend/constraints.txt` transitive; Docker and CI install with `-c constraints.txt`), and `userdata/tests/test_dependency_versions.py` fails the suite if the installed Django's major.minor doesn't match the pin. `predev`/`prestart` run `kill-port 3000 8000` first so a stale process from a previous run doesn't silently block startup. `backend/start.py`'s pre-startup steps run in order — DB create → migrate → `createcachetable` (throttle counters' `DatabaseCache` table; no-op under DEBUG's LocMem) → best-effort `flushexpiredtokens` (expired session-token rows, capped at 60s; the Docker entrypoint runs the same step) → best-effort `prune_media_cache` (`TMDBMediaCache` rows past `CACHE_TTL_DAYS` that no watched entry uses; watched titles' stale rows stay as the outage fallback; 60s, both startup paths) → best-effort `compute_recommendations` (capped at 30s, `subprocess.TimeoutExpired` caught and skipped) → `runserver`. That timeout matters: without it, a slow/hung TMDB call during the cache-warm step blocks `runserver` from ever starting, and `npm run dev` just never finishes booting Django with no error surfaced.
- **Dev API traffic is same-origin**: `package.json`'s `proxy` (the IPv4 loopback address, port 8000) makes CRA forward `/api/**` and `/media/**` to Django, and the clients default to relative URLs (`/api`, `/api/tmdb`, media `""`). Production sets the same values through `REACT_APP_*` in `Dockerfile.frontend`. Don't go back to `http://${hostname}:8000`. Cross-origin calls need a CORS preflight per new URL, and on the dev machine (Windows) `localhost` resolves to `::1` first while `runserver` binds IPv4 only, so every new connection paid an IPv6 fallback (2 s from Python, ~300 ms in Chrome; measured in `speed-up-pages`). For the same reason, CRA itself should listen dual-stack: root `.env` `HOST=::` (`.env.example`), not `0.0.0.0`. Scripts and tests that call Django directly use the IPv4 loopback address on port 8000 (as the `proxy` does), not `localhost`.
- TMDB requests are proxied by Django itself (`backend/userdata/tmdb_proxy_views.py`'s `tmdb_proxy`, mounted at `api/tmdb/<path:tmdb_path>`, `AllowAny` since it's public data) — there is no separate Node/Express layer (removed in 0.15.4). It uses a shared module-level `requests.Session()` with retry/pooling (`HTTPAdapter`+`Retry`), not a bare per-call `requests.get()` — a movie/TV detail page fires ~6 concurrent proxy calls, and a fresh-handshake-per-call approach saw sporadic transient 502s under that burst. The whole proxied call runs under a wall-clock deadline, `PROXY_DEADLINE_SECONDS` (`tmdb_client.call_with_deadline`), and `test_tmdb_proxy` pins it 5s under the `gunicorn --timeout` in `docker-entrypoint.sh`. Per-attempt timeouts and retries (`CONNECT_TIMEOUT`, `READ_TIMEOUT`, `RETRY`) can't bound a call: urllib3 tries the connect once per address DNS returns, so don't go back to a model of attempts × timeouts. Retune them freely for the reset case they handle. Successful (`200`) proxy responses are cached in their own `tmdb` cache alias (LocMem `tmdb-proxy` under DEBUG, `DatabaseCache` table `tmdb_proxy_cache` in prod, created by the existing `createcachetable` step), keyed on path + forwarded params, with TTLs by path (`cache_ttl`: lists 10 min, genre/configuration 24 h, everything else 6 h) and an `X-Cache: HIT|MISS|BYPASS` header. Never put it in `default`: culling there evicts throttle counters. The same holds for followed people's TMDB credits, which have their own alias, `person_credits` (`social_views.credits_cache()`). Any new bulky or user-growable cached data gets its own alias too, never `default`. A LocMem alias also needs its own `LOCATION`, or it shares default's store, and `backend/conftest.py`'s autouse fixture clears each TMDB alias between tests. Requests with `session_id`/`guest_session_id`, and `account`/`authentication` paths, bypass the cache, because that data is per user. Backend tests get an empty `tmdb` cache from the autouse fixture in `backend/conftest.py`. The frontend TMDB client (`src/api/tmdb.ts`) sends the user's JWT so `TmdbProxyThrottle` keys per user, not per NAT'd IP. On a 401 (an expired token on this `AllowAny` view) it retries once without the token, and it never logs out or refreshes: refresh stays only in `userApi`. Every fetcher goes through `sharedGet`, which shares identical GETs still in flight, so StrictMode's double mount (and two components asking at once) costs one request. Add new fetchers through it, not `api.get`. Detail/person pages read `:id` only through `useValidId()` (`src/hooks/useValidId.ts`), because a decoded `..%2F` id would turn a proxy path into a request to another app endpoint, token included. Any new page that builds a proxy path from a route param must do the same. The notifications poll has the same kind of budget: `NOTIFICATIONS_BUDGET_SECONDS` (with `NOTIFICATIONS_MAX_FETCH` people per poll), pinned by `test_notifications` at ≤ that `--timeout` − 10. So do followed-people recommendations (`FOLLOWED_RECS_BUDGET_SECONDS`, `test_followed_people`) and Stats' cold genre lookup (`GENRE_LOOKUP_TIMEOUT` × 2 calls, `test_stats_genres`). A person's credits are acting plus every crew job, one per `(id, media_type)`, with Talk (10767) and News (10763) appearances dropped (`social_views._fetch_person_credits`, `is_talk_or_news`; "Because you like {actor}" skips them too). A poll reads each person's recent summary (`person_recent:v2:<id>`, credits dated −32/+2 days around the fetch), not their new-work list (`person_new:v2:<id>`, credits from the last `NEW_WORK_DAYS` (730) or later, which only the "New from {name}" sections read, newest first, no rating floor): both are written together on every fetch, so keep it that way or a poll's memory grows again. Bump the key version when what's cached per person changes. Unread means "not seen at the last mark-seen": mark-seen stores every window item the user had (`NotificationCheckpoint.seen_items`, computed by the poll's own `_window_items` from the cache only, no TMDB call, capped at `MAX_SEEN_ITEMS`), and a checkpoint with `seen_items` null (from before `follow-crew-credits`) keeps the date rule until its next mark-seen. Any new endpoint that waits on TMDB during the request needs a budget and a pin like these: run each TMDB call through `tmdb_client.call_with_deadline(fn, deadline, ...)` (`TMDB_CALL_DEADLINE` for single calls, as the TMDB connect and rating endpoints do; Stats uses `GENRE_LOOKUP_DEADLINE`), and pin calls × deadline under the timeout. The callable runs on a pool thread, so it does HTTP only. A TMDB call whose order doesn't matter and whose result nobody waits for (session revokes) goes after the local change through `tmdb_client.revoke_in_background`-style on-commit background work, never before it: change the local state first, so a killed request can't leave a revoked session stored or an account undeleted. Rating sync stays in the request, bounded, because background syncs from different server processes could reach TMDB out of order.

- **Docker production stack**: the backend container runs as non-root `app` (uid 10001) with `/app` read-only to it. Only `/app/media` (the `media_data` volume) is writable, so anything that writes elsewhere at runtime fails in Docker but works under `npm run dev`. It applies only the migrations baked into the image (no host bind mount, no `--run-syncdb`). The image carries no tests or dev-only files (`backend/.dockerignore`: `userdata/tests/`, `conftest.py`, `pytest.ini`, `pytest_dev_env.py`, `requirements-test.txt`, `start.py`; asserted by `test_compose_config.py`), so runtime code must never import from them. The root `.dockerignore` keeps `.git`, `.github`, `.claude`, `openspec`, `docs`, `scripts` and tool caches out of the frontend build context. `nginx.conf` sets `server_tokens off`. Security headers, including the enforced Content-Security-Policy, live in `nginx.conf`, not Django. A new external origin (image host, embed, font, API) must be added to that CSP or browsers block it in production while dev (no CSP) keeps working. `Dockerfile.frontend`'s `INLINE_RUNTIME_CHUNK=false` is what lets `script-src 'self'` work without an inline exception, so don't remove it (CI's build sets it too). `nginx.conf` serves `/static/` with `try_files $uri =404` (a missing old chunk is a 404, not `index.html`) and sends `Cache-Control: no-cache` for `index.html` through a `map` + server-level `add_header`. Hashed `/static/` files get `public, max-age=31536000, immutable` the same way (`$static_cache_control`), but through an `add_header` *without* `always`, so a missing chunk's 404 is never cached for a year. `gzip` is on at server level for the app's text assets and `off` in `/api/` and `/media/` (BREACH; see `docs/ARCHITECTURE.md`). CI's `docker` job builds both images and runs `.github/scripts/smoke-frontend.sh` against the real nginx, so a header change has to pass there too. Never put an `add_header` inside a `location`: it drops every inherited security header there (`test_nginx_conf.py` fails on it). Access logs go through the `redacted` `log_format`, whose URI and referer maps blank `/reset-password/…` and `/tmdb-callback?…`; a new route that carries a token in its URL needs the same entry. With `DEBUG` off, startup also fails without an explicit `EMAIL_BACKEND`, without `FRONTEND_URL` as an absolute `http(s)` URL (reset links are built from it, never from `Host`), or without valid `TMDB_SESSION_KEYS` (Fernet keys; first encrypts, all decrypt; `DEBUG` adds one derived from `SECRET_KEY`, last, so it only decrypts once real keys are set). A user's TMDB `session_id` is stored only through `EncryptedSessionField` (`userdata/secret_fields.py`, `encrypt-tmdb-session`): never store a TMDB credential in a plain field, never filter on its value (encryption is randomized), and a value no key can read comes back `""`, i.e. not connected. Key rotation is `rotate_tmdb_sessions`. A new env var read in `settings.py` must be added to `backend/.env.example`, or `test_app_config.py` fails. There is no Django admin: don't add `django.contrib.admin` back. The db password lives only in `.env.db` (`POSTGRES_PASSWORD`, which the db container reads alone and `settings.py` falls back to), never in `.env.docker`. `TRUSTED_PROXY_COUNT` is 1 in `docker-compose.yml` (the settings default is 0, right for `npm run dev`) and can be overridden from the shell or root `.env`. With `DEBUG` off the API renders JSON only (no browsable API). gunicorn runs threaded workers (`--workers 3 --worker-class gthread --threads 8`): a request waiting on TMDB holds a thread, not a whole worker. Under `gthread`, `--timeout` guards a hung worker process rather than killing a slow request, so the endpoint TMDB budgets are what bound a request; keep `--timeout` explicit, since the budget pins read it. The shared TMDB pools (`tmdb_client.DEADLINE_POOL_SIZE`, the proxy's `SESSION_POOL_SIZE`) stay at least the thread count (`test_startup_warmup` pins it). Module-level state must stay lock-guarded or a harmless cache: several requests run at once per process. With `DEBUG` off, DB connections are kept 60 s (`CONN_MAX_AGE`, env-overridable), one per request thread. Under `DEBUG` it stays 0, because `runserver` gives every request a new thread, so a kept connection is only left open, never reused.

## Conventions to reuse, don't reinvent
- **Page titles and announcements**: every page calls `usePageTitle(name)` (`src/hooks/usePageTitle.ts`), which sets the tab title to "<name> · CINE DB"; detail, person and list pages pass the loaded name (a generic one until then) plus `{ loading }`, true until the load settles either way. Detail and person pages get both through `detailPageTitle(state, headings)`, which names what the page shows: "Page Not Found" for an invalid id, the page's own not-found or error heading on an error, and the generic name for a record that loaded without one. `App.tsx` keys `<Routes>` on the pathname, which also mounts a fresh detail page per id, so the previous subject never shows under a new address: keep that key. The page owns its title even while it renders `NotFoundPage`, because React runs the parent's effect after the child's, so a different parent title would win. `RouteAnnouncer` (mounted once in `App.tsx`) speaks the new page's title through a polite live region after an in-app navigation, only once a non-loading title from that page has held for `ANNOUNCE_SETTLE_MS`. A page's unmount clears the last title, so the previous page's title is never announced while a lazy route loads. A page that leaves `loading` true is never announced. The first load is skipped by comparing paths, not with a first-run flag, which StrictMode's replay would consume. It never moves focus, because focus moves would fight the scroll restores. A new page must call the hook.
- **Reduced motion**: `index.tsx` wraps the app in `MotionConfig reducedMotion="user"`, and `App.css` ends with a `prefers-reduced-motion` rule that cuts CSS transitions and animations (antd's too). JS-driven motion checks framer-motion's `useReducedMotion()` itself (Stats' `useCountUp`, `MarqueeTitle`). So does Recharts: every series gets `isAnimationActive`. Programmatic scrolls take `behavior` from `useScrollBehavior()` (`src/hooks/useScrollBehavior.ts`: `"auto"` under reduced motion, else `"smooth"`), because an explicit JS `behavior` beats the CSS rule. New JS animation or smooth scroll needs the same check.
- **Font size**: never hardcode `fontSize: N`. Import `FONT_SIZE` from `src/constants/typography.ts` (`caption` 12 / `body` 14 / `emphasis` 16 / `display` 28). Icon-scaling `fontSize` props (antd icons) are the one exception — those stay numeric.
- **Info tooltips**: use `<InfoTooltip title="..." />` from `src/components/InfoTooltip.tsx` (wraps antd `Tooltip` + `InfoCircleOutlined`) next to any label/stat that needs a one-line explanation. Don't hand-roll a new `Tooltip`+icon pairing.
- **Dates**: render with `formatDateDMY()` from `src/utils/formatDate.ts` — fixed `dd-mm-yyyy`, not locale-dependent `toLocaleDateString()`.
- **Whose day is it** (`user-local-dates`): two rules.
  - **"Today"** is the requesting device's time zone. `userApi`'s interceptor sends it as `X-Timezone`, and the backend reads it only through `backend/userdata/timezones.py` (`request_tz`, `local_today`).
  - **A past watch's day** is the zone it was logged in: `WatchedEntry.watched_tz`, read through `entry_day` / `entry_local`. Blank (pre-change or imported without a zone) falls back to the device's zone.
  - **Never derive a user-facing day from a UTC instant:** no `toISOString().slice(0, 10)` (use `localISODate`), and no `.date()` / `strftime` on `watched_at` (use the helpers). On the frontend, show a watch's date with `formatWatchedDate(iso, watchedTz)`, which adds the zone label only when the offset differs from the device's.
  - **Bad zones fall back to UTC, never 400/500.** Unknown names are stored blank.
  - **CORS:** dev is same-origin now (see "Dev API traffic"), but `X-Timezone` stays in `CORS_ALLOW_HEADERS` for anyone pointing a `REACT_APP_*` base URL at another origin. Any new custom request header needs the same.
  - **Aliases:** Chromium reports some zones under old ICU aliases (`Asia/Calcutta` for `Asia/Kolkata`). Compare offsets, never names.
- **Fonts**: Poppins is set once via `commonTokens.fontFamily` in `src/theme/antdTheme.ts`. Never add a per-component `fontFamily` override.
- **Brand mark, account pages, links and buttons** (`auth-pages-identity`): "CINE DB" is always `<Wordmark>` (`src/components/Wordmark.tsx`; its color is theme-scoped in `App.css`, gold in dark, brass `LINK_BRASS` in light, where gold measures 1.5:1). Sign in, Create account, Forgot and Reset password render inside `<AuthStage title="…">` (`src/components/AuthStage.tsx`: beam, wordmark as the page's `h1`, tagline, card with the page's `h2`); a new account page uses it too, never its own copy. Link colors (`colorLink`/`Hover`/`Active`) and primary-button text (`Button.primaryColor: ON_GOLD_TEXT`) are theme tokens in both configs, never per-page CSS, and not `colorTextLightSolid` (tooltips, badges and danger buttons need white there). `themeContrast.test.ts` pins them; light hover/active go darker, because a lighter brass drops under 4.5:1. The dark-mode wordmark glow is only on the account pages' stage. The stage adapts to height only through CSS (`svh` clamps and `max-height` steps in `App.css`), and `AuthStage` adds `interactive-widget=resizes-content` to the viewport meta while mounted (restored on unmount) so an Android keyboard shrinks the page there; don't put it in `public/index.html`, because app-wide it would lift the fixed `BottomNav` onto the keyboard.
- **Detail-page sections**: `MovieDetails.tsx` and `TVShowDetails.tsx` share `SectionHeader` (section divider+title), `WatchProviders` (streaming/rent logos), `MediaCardGrid` (poster-card grid for recommendations/similar/credits, default `limit=20`, optional `title`/per-item `subtitle`), and `ReviewsSection` (2-column review cards) from `src/components/`. Both pages render sections in the same order (Where to Watch → Cast → Recommendations → Similar → Trailers → Images → Reviews). Each page loads all of them in **one** TMDB request (`fetchMovieDetails`/`fetchTVDetails` with `append_to_response`, note the literal `"watch/providers"` key), and maps every part through the shape guards in `src/utils/appended.ts` (`resultsOf`/`arrayOr`/`objectOr`), so a missing or malformed part empties only its section. A new section adds a part to that list, never a second request. Trailers go through `TrailerEmbed` (thumbnail button first, the `youtube-nocookie` player only after activation). Don't re-inline a copy in one of the two detail components — fix/extend the shared one. `PersonPage.tsx` also reuses `MediaCardGrid` (uncapped, `limit={array.length}`) for its Movies/TV credit tabs instead of a local card component. Both Recommendations and Similar are additionally run through `filterByGenreOverlap()` (`src/utils/filterByGenreOverlap.ts`) before being handed to `MediaCardGrid` — keeps only items sharing ≥half the opened title's genres, falls back to the unfiltered list rather than showing nothing. Reuse this util for any new genre-filtered grid instead of writing another overlap check.
- **Nav icon tooltips**: `Sidebar.tsx` and `BottomNav.tsx` both use `useFlashTooltip()` (`src/hooks/useFlashTooltip.ts`) to force-show a nav icon's `Tooltip` for ~1.4s right after it's clicked (`open={flashKey === key || undefined}`), since the tablet icon-rail and phone bottom-nav have no visible text label to confirm the destination. Reuse this hook for any new icon-only nav control instead of a bespoke timeout/state pair. Nav entries are real links (`a11y-motion-titles`): the sidebar menu's label and icon are `<Link>`s (the icon one out of the tab order), and `Menu.onClick` navigates only when the click didn't land on the anchor, so a plain click pushes one history entry; BottomNav core buttons are antd `Button href` with a plain click taken over through `isPlainClick()`, and its More drawer entries are `<Link>`s. Keep new nav entries the same way. Which entry is highlighted comes from `navSection()` (`src/utils/navSection.ts`) in both navs: a section with its own sub-pages (`/lists` → `/lists/3`) is listed there, while detail routes like `/tv/1396` belong to no entry.
- **Library item cards**: `WatchlistPage.tsx`, `WatchedPage.tsx`, and `ListDetailPage.tsx` share `LibraryItemCard.tsx` (poster + `Card.Meta` + icon action buttons) for their item grids. `PeoplePage.tsx`, `SearchPage.tsx`'s People tab and `FollowingPage.tsx` share `PersonCard.tsx`. Don't hand-roll another `Card`/`Row`/`Col` poster grid — extend one of these. `LibraryItemCard.tsx`'s outer `motion.div` needs `height: "100%"` for cards in the same grid row to render equal height (antd's `Col` stretches to the row's tallest sibling by default, but only the wrapper explicitly filling that height makes the visible card box follow) — don't drop it when touching this component.
- **Cards that open a page are `CardLink`s**: any poster card/thumbnail that navigates to a detail or person page goes through `CardLink` (`src/components/CardLink.tsx`), a real router `<Link>` with an `href`, so Tab/Enter, Ctrl/middle-click new tab and the focus outline (`.card-link:focus-visible`, light/dark pair in `App.css`) all work. Never use a clickable `div`/`Card` `onClick` for this. When the target needs click-time router state (scroll position, `stashReturnState()`), pass `onNavigate` and keep `to` as the real href. A plain click or Enter calls `onNavigate`, and modifier clicks open `to` natively. Whole card = link only when the card has no buttons of its own (`MediaCardGrid`, cast, Calendar, Home strip). If it has buttons (`PersonCard` Follow, `LibraryItemCard` actions), only the poster is the link, because a button nested in a link is invalid. `PersonCard` also passes `stopPropagation`, because its card-level mouse `onClick` stays. `LibraryItemCard` needs a `to` prop from its callers. There are no exceptions left: the Recommendations/Following `SectionRow` cards and the Lists page cards were converted in `surface-failures-2`, and the Movies/TV/Anime grid card (now the single `MediaCard.tsx`) in `fix-detail-and-nav` (all poster-only links, since those cards have buttons). Search's Movies/TV tabs render that same `MediaCard` (`honest-states-a11y`), so don't hand-roll a search card again. `MediaCard` serves movies and TV alike (`merge-media-cards`): callers spread `toMediaSummary(item, "movie" | "tv")` (`src/utils/mediaSummary.ts`, which maps TMDB's `title`/`name`) into its flat props and pass a stable `onKnowMore` (Home/Anime read the latest state through a ref behind a `useCallback`, Search's tabs `useCallback` theirs), so `memo` holds. Its writes are explicit `add`/`remove`, never `toggle`, so the toast names what ran and a stale render can't mark a title without `MarkWatchedModal`. Don't split it back into per-type copies. A card's action buttons name their title (`"Add to watchlist: <title>"`), so a screen reader can tell a grid's buttons apart. Links that aren't cards follow the same rule: notification items are `CardLink`s, and the hero's "View Details" is an antd `Button` with `href` whose plain click is taken over with `isPlainClick()` (exported from `CardLink.tsx`).
- **Watched status source of truth**: there is exactly one "is this watched" boolean per title — the shared `WatchedContext` (`isWatched(id, type)` / `toggleWatched(...)`). `WatchlistEntry` has no `watched` column; don't add one back or otherwise let a page maintain its own separate watched flag — it will drift out of sync with whatever else marks/unmarks the same title.
- **Shared UI constants**: `IMG_URL` (`w500`: detail poster, cast, galleries, person images), `POSTER_URL` (`w342`, every grid poster card), `POSTER_THUMB_URL` (`w185`, small poster thumbnails e.g. HomePage's recently-watched strip and the notification list), `STILL_URL` (`w300`, episode stills), `LOGO_URL` (`w92`, provider logos), `BACKDROP_URL` (`w1280`, hero/detail backdrops; `BACKDROP_ORIGINAL_URL` only for the full-screen image preview), `YT_THUMB_URL` (trailer thumbnails, whose host is in the nginx CSP `img-src`), `RATING_GOLD`, `LINK_BRASS` (light theme links and wordmark), `WATCHED_GREEN`, `RATING_WARN`, `RATING_BAD` live in `src/constants/ui.ts`, as do three fixed state/on-fill colors: `IN_WATCHLIST_BLUE` (the active watchlist icon; antd's `colorPrimary` here is gold, so it can't be a token), `ON_GOLD_TEXT` and `AVATAR_INITIALS_TEXT` (text on a fill that doesn't change with the theme). An idle watched/watchlist icon takes its color from `useActionIconColor()` (`src/hooks/useActionIconColor.ts`: gold in dark mode, the theme's `colorText` in light), never an inline `theme === "dark" ? … : "#000000"`; provider deep-links (`PROVIDER_SEARCH_URLS`) live in `src/constants/providers.ts`. Color *rules* live in `src/utils/colors.ts`: `ratingColor(vote)` (TMDB score tag: ≥8 green, ≥5 amber, else red) and `avatarColor(username)` (stable fallback avatar background) — import these instead of writing another local `getRatingColor`/palette hash (there were 5 and 2 copies until `frontend-polish`). Don't hardcode hex colors or TMDB image URLs inline — for one-off section-header/divider colors, and for any text/fill/tooltip that must read in both themes (Stats' labels, heatmap and chart tooltips), use antd's `theme.useToken()` (e.g. `colorTextTertiary` for empty-state icons (`colorTextQuaternary` measured 1.8:1 on the light background, too faint), `colorFillSecondary` for `PosterPlaceholder`, `colorTextSecondary`, `colorTextTertiary`, `colorFillTertiary`, `colorBgElevated`, `colorBorderSecondary`) over a literal hex or `rgba(255,255,255,…)`, per `ProfileModal.tsx`/`StatsPage.tsx`. The one deliberate exception is Stats' chart series palette and heatmap green scale, which are named constants at the top of `StatsPage.tsx`, fixed so the hues stay distinct in both themes. Outside `constants/`, `theme/`, `utils/colors.ts` and those, `src/` has no color literal.
- **No-poster fallback**: use `<PosterPlaceholder className="..." style={{...}} />` (`src/components/PosterPlaceholder.tsx`) wherever a poster/profile image might be missing — pass the same className the real `<img>` would use (it takes optional `children` to replace the "No Image" text, as the Episode Guide's hidden still does) (`movie-poster-img`, `rec-card-img`, `cast-card-img-lg`, `detail-poster-img`) so it picks up the same aspect-ratio/border-radius. It's a real DOM element (renders "No Image" text that inherits the app's Poppins font), not an image — don't reintroduce an SVG-data-URI placeholder (`NO_IMAGE` was removed for exactly this reason: text baked into an `<img src="data:...">` SVG can't see the page's `@font-face`, so it could never match the rest of the UI's font). Two call sites (`PersonPage.tsx`, `StatsPage.tsx`) pass an extra `style={{ aspectRatio: "2 / 3" }}` since their real-`<img>` counterpart has no CSS class enforcing one — check whether yours needs the same before assuming the className alone sizes it. The movie and TV cards (now `MediaCard.tsx`), `RecommendationsPage.tsx`, and `SearchPage.tsx`'s Movies/TV tabs were all still falling back to a `placehold.co` SVG `<img>` instead of this component until 0.15.7 — check for that pattern (`poster_path ? <img.../> : "https://placehold.co/..."`) before assuming every card grid already follows the convention.

- **Per-endpoint throttle scopes**: `LoginThrottle`/`RegisterThrottle`/`PasswordResetThrottle`/`PasswordResetConfirmThrottle` (`auth_views.py`; reset request and confirm are separate buckets on purpose) established the pattern — subclass `AnonRateThrottle` (or `UserRateThrottle`, for endpoints authenticated users hit too) with a `scope` attribute, register the rate in `settings.py`'s `REST_FRAMEWORK.DEFAULT_THROTTLE_RATES`, apply via `@throttle_classes([...])`. `TmdbProxyThrottle` (`tmdb_proxy_views.py`, `120/min`), `NotificationsThrottle` (`notifications_views.py`, `30/min`) and `FollowedRecsThrottle` (`social_views.py`, `followed_recs: 30/min`) extend this to the TMDB-cost endpoints — use `UserRateThrottle` as the base for anything `AllowAny`-or-authenticated that costs real TMDB quota per call, not `AnonRateThrottle` (which no-ops entirely for authenticated requests, per DRF's own `get_cache_key`). Any path that frees a username (account deletion, a rename) clears the old name's row in the same transaction, so the next owner of that name doesn't inherit its failures. It keys on the exact username (`_login_failure_key`), as sign-in matches it: folding case let failures on `Alice` lock out `alice`. A profile update needs `current_password` to change the email, the username (exact compare, a case change included; the address on file gets a notice on commit) or the password. New passwords go through `AUTH_PASSWORD_VALIDATORS` with the account's details, `UserAttributeSimilarityValidator` included at Django's default 0.7 threshold: registration validates at object level against an unsaved `User(username, email)`, the profile against a copy carrying the update's values. Any new endpoint that checks the user's password must do the same, and never move the counter back into the cache (`DatabaseCache.incr` is a non-atomic get + set that resets the expiry to 300 s, which LocMem-backed tests can't see).
- **Bare `except Exception:` convention**: narrow to what the try block can actually raise — `(requests.RequestException, ValueError)` for a TMDB fetch alone, add `KeyError`/`TypeError` if the code does direct dict indexing (`c["id"]`) instead of `.get()`, add `django.db.Error` if a DB write follows. A handful of sites are legitimately broad on purpose (`recommendations.py`'s `_refresh_cache` and the `f.result()` loop in `_compute_personalized`, `compute_recommendations.py`'s per-user batch loop, `auth_views.py`'s `send_mail` call) — each has a comment explaining why (heterogeneous TMDB+numpy/sklearn+DB operation mix in a background/batch context, or a mail backend whose exception type varies by deploy). Match that judgment for new code — reflexive bare-except is the default to avoid, not broad-catch itself. Inside a TMDB `except`, split out a 404 with `is_not_found(e)` before treating the error as a failure (see the next bullet).
- **Upstream failures and worker threads (backend)**: never write a placeholder (empty genres, empty credits) when a TMDB call fails. Keep the existing value, or store nothing so the next call retries (`_store_media_cache`, `_fetch_followed_people_credits`). A TMDB 404 is not a failure: check it with `tmdb_client.is_not_found(e)`, never call `health.mark_failed()` for it, and store its empty result like any answer (empty `TMDBMediaCache` row, `[]` person credits, `metadata_settled`). Otherwise one deleted title or person freezes recommendations and is refetched forever. The same holds for a whole result: a recommendations refresh goes through `save_recommendations()`, which keeps the stored row when a TMDB call failed (marked on the shared `FetchHealth`) and the new result has fewer non-empty sections. Pass it `started` (when the compute began): it skips the write when a compute that started later already saved (`source_started_at`, under `select_for_update`), and returns `SAVED` / `KEPT_OUTAGE` / `SUPERSEDED`. Only `KEPT_OUTAGE` sets the failure backoff. A new except-branch in a compute that drops content must call `health.mark_failed()`. In a `ThreadPoolExecutor`, workers only do HTTP. DB queries and `django.core.cache` calls stay on the calling thread, because the production cache is DB-backed and each worker thread would otherwise open and leak its own connection. Watched-title metadata (genres, language, year) is filled only through `metadata_backfill.py` (`request_backfill` for fire-and-forget, `backfill_entries` when the caller needs the data), never by a new ad-hoc thread. It fetches at most `MAX_PER_RUN` titles per run. Any background TMDB title fetch for a user (this backfill, the recommendations cache fill, anything new) first takes a grant from `tmdb_budget.take(user_id, n)` (1,000 per user per UTC day, a `TmdbTitleBudget` row locked with `select_for_update`), and a short grant is never a failure. Also, and "TMDB has nothing more for this title" is the DB field `WatchedEntry.metadata_settled`, not process memory, so other workers and restarts don't refetch it. Only a TMDB 404 settles a title. A title TMDB lists without genres stays unsettled and is fetched again `METADATA_RECHECK_DAYS` (30) after `metadata_checked_at`, because new titles get genres and a release year later. TMDB `session_id`/`guest_session_id`/`request_token` values are credentials: log only an exception's type around calls that carry them (`RedactingFormatter` strips them too, as a backstop).
- **Recommendation refresh triggers**: schedule a background recompute only via `recommendations.request_refresh(user_id, rerun_if_running=...)` (or `_start_refresh_if_needed` from views), never by starting a thread directly. It coalesces per user (one running + at most one follow-up), and `signals.py` defers it with `transaction.on_commit`. A thread-per-trigger path is how clearing a 500-item watched history used to start 500 concurrent TMDB-heavy refreshes. At most `MAX_CONCURRENT_REFRESHES` (4) refreshes compute at once per process (a semaphore in `_refresh_thread`). Background metadata backfills have their own cap, `MAX_CONCURRENT_BACKFILLS` (2), taken in `_run_backfill` before any DB work; the synchronous backfill inside a refresh doesn't take it (the refresh slot already bounds it). A refused result (`save_recommendations` returned False) sets a 10-minute backoff marker (`rec_refresh_backoff:<id>` in `default`, set with a timeout, never `incr`), and the endpoints' shared `_recommendations_response` doesn't trigger on a stale row while it's set. Only data-change triggers (`rerun_if_running=True`) override it, so keep poll-driven triggers on `rerun_if_running=False`. One refresh fetches at most `MAX_FILL_PER_RUN` (200) titles' details, missing ones first. Any new early-exit in the thread target must still call `_finish_refresh(user_id)`, or that user stays "pending" until the process restarts. Rating writes trigger it too (`fix-recs-correctness`), from the rating views rather than a signal: a create, a score change, a delete, or a bulk import that adds. A review-only edit doesn't. Genres are counted and queried only through `genre_families.py` (recommendations and Stats). Taste clustering uses only titles that have genres and weren't rated 4 or below. A cluster whose top genres can't be asked together for a type falls back to each genre alone (`_genres_for`). Candidates exclude every watched **and rated** title. TMDB genre ids are specific to a media type, so never pool raw ids across movie and TV or send one type's id to the other's `/discover`.
- **Serializer input bounds**: a hand-declared camelCase serializer field (`posterPath = CharField(source="poster_path")`) loses the model's `max_length`/`choices`/range, so restate them. Use `FiniteFloatField` for every float input, never plain `FloatField`: it accepts `"NaN"`, which makes every later read of that account 500. Use `MediaIdentityMixin` for any new `mediaId`/`mediaType` serializer, and `INT32_MAX` for id bounds. Endpoints that read the body directly go through a small input serializer, not `request.data.get(...)`, which 500s on a JSON array body.
- **Imports, backups and paginated lists**: new bulk endpoints go through `bulk_import()` (`backend/userdata/bulk_import.py`): create-only and all-or-nothing per request, with `bulkImport()` in `userApi.ts` chunking at 500 entries or `BULK_MAX_BYTES` (~2 MB of JSON, under Django's default 2.5 MB body limit), whichever comes first. List items use the same path (`POST /api/lists/<id>/items/bulk/` via `bulk_import(scope={"user_list": ...})`, client `bulkAddListItems()`), so never add list items one `POST` each in an import. Undated rows go in reverse file order so the list shows file order. Import poster/score lookups go only through `lookupImportPosters` (`src/utils/importPosters.ts`, over `pacedLookup`), which stays under the per-user `tmdb_proxy` rate and waits out a 429. They run only for rows the file doesn't give both a poster and a score, and the file's values take precedence, so re-importing the Watched export makes no lookups. That rule lives in `lookupImportPosters` itself (callers pass every row with the file's `posterPath`/`voteAverage` and read back final values), so the three import dialogs can't drift apart again. It looks each title (type + id) up once per import and counts missing posters per title, so a backup with a title in four sections makes one call. `undefined` score means unknown; any number, 0 included, is given. Both CSV readers parse every column through one helper each in `csvParse.ts` (`parseTitle`, `parsePosterPath`, `parseScore`, `parseRuntime`, `parseBoundedText`, `parseUserRating`, `normalizeWatchedAt`), with the bounds restated from the bulk serializers: a value the server would reject is dropped for that row only (a title is cut to 500, a review over 5,000 is dropped, a rating row without a valid rating is skipped), because one bad cell would fail its whole 500-row chunk. Lengths count code points (`charLength`/`cutChars`) like Django's `max_length`, never `.length`: a cut through an emoji leaves a lone surrogate that PostgreSQL refuses. Times may be up to 5 minutes ahead of the device clock, the server's `BULK_TIMESTAMP_SKEW`. A new imported column gets a helper there, never inline parsing. A backup's score is taken as given: blank or bad is 0, and a row with a poster is never looked up for it (`fix-library-backup-edges`). A row looked up for its missing poster anyway keeps TMDB's score when its backup score is 0 (`fix-restore-text-edges`). Never loop over rows with bare TMDB calls. A model keyed by one id instead of `(mediaId, mediaType)` (follows, episode progress) passes `bulk_import(identity=…)`. Counts come from what the database really inserted (`insert_ignoring_conflicts`). Read every CSV with `parseCSV`/`parseCSVForImport`/`parseBackupCSV` (`src/utils/csvParse.ts`), never a line split, because quoted fields contain newlines. Write every CSV through `buildCSVString` (`src/utils/export.ts`): its `escape()` prefixes a `'` to cells starting with `=` `+` `-` `@` tab CR (or `'`), so spreadsheets don't run them as formulas, and `parseCSV` strips exactly that one `'` back off. A new exporter or importer that bypasses either breaks the lossless round trip. The Watched page's own CSV (`handleExport`) carries `watched_at`, `watched_tz`, `runtime_minutes`, `platform` and `poster_path`, and `parseCSVForImport` reads each back, dropping a bad value for that row only (one out-of-range value would fail the whole batch): a new export column needs its import side too. Save every file through `downloadBlob()` (`src/utils/export.ts`): it attaches the anchor and revokes the object URL a tick after `click()`, because revoking it synchronously cancelled downloads in some browsers. Backup format changes stay additive in `src/utils/backup.ts`, so older backups keep importing. `DefaultPagination` accepts `page_size` up to 500, and the watched/watchlist/ratings hooks load with `fetchAllPages(api, url, { pageSize: LIBRARY_PAGE_SIZE })`. Lists (nested items) and followed people keep the default 100. Any paginated `order_by` on a timestamp needs an `-id` tiebreaker: bulk imports create ties, and `fetchAllPages` then returns duplicates and skips rows. Each library list query has a matching `(user, -<date>, -id)` index declared in the model's `Meta.indexes` (`fix-db-layer`; `test_list_indexes.py` ties it to the view's `order_by`). Never add an index in a migration alone: the next `makemigrations` generates its removal, which is how 0009 dropped 0008's.
- **Uploads are typed by content, not by name**: avatar files get their extension from PIL's decoded `Image.format` (`avatar_upload_path` whitelists `jpg`/`png`/`webp`), never from the client filename or declared content type. `/media/` is served with a content type guessed from the extension, so a client-chosen `.html` name was stored XSS on the app's own origin. Apply the same rule to any future upload. Avatars are also re-encoded (`_reencode_avatar`: EXIF dropped, orientation applied), so never store the uploaded bytes as-is.
- **Health endpoint stays unthrottled**: `health_views.health` has `@throttle_classes([])`. Compose polls it every 10s, so any throttle (even the anon default) eventually marks the container unhealthy. Don't remove it, and don't route new orchestrator probes through a throttled view.
- **Token refresh uses a custom view, not simplejwt's stock one**: `urls.py`'s `auth/token/refresh/` route is wired to `SafeTokenRefreshView` (`auth_views.py`), which wraps `TokenRefreshSerializer.validate()`'s unguarded `User.objects.get(...)` and converts a since-deleted token owner into a clean `InvalidToken` (401) instead of an unhandled 500. Don't swap this back to `rest_framework_simplejwt.views.TokenRefreshView` — that regresses a confirmed, reproduced bug (verified via a direct `APIRequestFactory` repro: delete a user, replay their still-unexpired refresh token, stock view 500s / this view 401s cleanly). Its serializer also enforces the `hash_password` claim (`CHECK_REVOKE_TOKEN`), which the stock one checks only on access tokens. That check is what stops a refresh racing a password change from surviving revocation (`test_password_bound_tokens.py`). Don't turn `CHECK_REVOKE_TOKEN` off, and issue tokens only through `RefreshToken.for_user()` (`_tokens_for_user`), which stamps the claim.
- **`ALLOWED_HOSTS` wildcards under `DEBUG`**: `settings.py` appends `"*"` to `ALLOWED_HOSTS` when `DEBUG` is true, mirroring `CORS_ALLOW_ALL_ORIGINS`. This matters because the frontend now calls Django directly (no Express layer in between since 0.15.4) — a LAN device hitting the dev server by IP (`<host-lan-ip>:8000`) sends that IP as its real Host header, and without the wildcard Django 400s with `DisallowedHost` before the view ever runs. Prod is fail-closed: `DEBUG` defaults to off when unset, and with it off `settings.py` raises `ImproperlyConfigured` on an empty or wildcard `ALLOWED_HOSTS` (so Docker/LAN hosts must be listed explicitly, including `localhost` for the compose healthcheck). `npm run dev` gets `DEBUG=True` from `start.py`'s `os.environ.setdefault`, and pytest gets it from `backend/pytest_dev_env.py` (loaded via `-p` in `pytest.ini`, because a root `conftest.py` runs after pytest-django has already imported settings) — don't move that default into `conftest.py`, and don't flip the settings default back to `True`.

## Verification
- Typecheck: `npm run typecheck` (app plus e2e specs via `e2e/tsconfig.json`; always run after TSX/TS edits). Lint: `npm run lint` (`src` and `e2e`, `--max-warnings=0`; CI fails on any warning). It runs with `--cache` (`.eslintcache`, gitignored), so a repeat run re-lints only changed files; delete the file if a config change seems ignored. `package.json`'s `eslintConfig.overrides` turns off, for `e2e/` only, the three Jest/Testing Library rules that misfire on Playwright (`prefer-screen-queries`, `valid-expect`, `valid-title`); add another only for a rule that misfires, never to silence a real finding. Backend CI also runs `ruff check backend/` and `makemigrations --check --dry-run`, so run both before pushing backend changes. Run `manage.py` with `DEBUG=True` in the environment, as CI does: without it, fail-closed settings refuse to load. Don't run the backend pytest at the same time as Playwright: the CPU load makes `page.goto` time out. ruff is pinned in `backend/requirements-test.txt` (and `constraints.txt`); bump the pin on purpose, in both files, since `test_dependency_versions.py` fails when the installed ruff differs.
- **Everything CI runs is pinned** (`harden-ci-3`), so a bump is a deliberate edit, never a floating tag. Actions are `owner/repo@<40-hex sha> # vX.Y.Z`: to bump, resolve the new tag's commit with `git ls-remote --tags https://github.com/<owner>/<repo>` (take the peeled `^{}` line for an annotated tag) and replace SHA and comment together. The workflow has top-level `permissions: contents: read`; a job that needs more declares it itself. Base images are `name:<exact version>@sha256:<index digest>` (both Dockerfiles, compose's Postgres), and `test_compose_config.py` fails on a `FROM`/`image:` without a digest. Bump by reading the multi-arch index digest for the new tag from the Docker Hub registry, keeping Node on 22. `wait-on` is an exact devDependency and CI calls it with `npx --no-install`. The Python e2e env is `e2e/python/constraints.txt` (`pip freeze` from a fresh venv after `pip install -r e2e/python/requirements.txt`; regenerate the same way). `@playwright/test` in `package.json` is exact and must equal the pip `playwright` pin: `test_dependency_versions.py` fails when they differ, so bump both (and regenerate the constraints) together.
- No Docker on the dev machine: `nginx.conf` and Dockerfile changes are checked locally only statically (`test_nginx_conf.py`), and for real only by CI's `docker` job (`.github/scripts/smoke-frontend.sh` against the built frontend image). Say so when reporting such a change as verified.
- **Live TMDB checks** (`backend/userdata/tests/test_tmdb_live.py`): every other test mocks TMDB, so only these see real data. Run `RUN_LIVE_TMDB=1 pytest -m live_tmdb` from `backend/` (needs the real key in `backend/.env`; about a minute). Without the flag every live check skips, so plain `pytest` and CI stay offline; never make the key alone enable them. Run them before archiving any change that adds or changes a TMDB request. A new feature that reads TMDB adds a shape check there (frontend requests through the `/api/tmdb/` test client with the frontend's params, backend ones through the backend function). A fix to what a TMDB query returns adds a query-sanity check there (backlog 35: Calendar coverage and sorts; 36: crew credits). When a frontend param the file restates changes, update its copy: the always-on drift checks fail for the `append_to_response` lists and the Anime keyword. Failure output must never carry the API key: backend calls go through `backend_call()`, and upstream logs are muted.
- TS e2e: `npx playwright test`. `playwright.config.ts` starts only the CRA dev server (`npx react-scripts start`) because every spec mocks its API calls; locally it reuses a running `npm run dev`. CI runs it in the `e2e-ts` job (Node 22, both projects), split into 3 shards (`--shard=N/3`, one runner each, one worker per runner) under a Playwright `globalTimeout` of 12 min, below the job's 15-minute cap, so an overrun fails with its report instead of a bare cancel (the unsplit suite outgrew the cap and was cancelled from 0.28.2 to 0.30.0). Add a shard when a shard's run nears 12 min; don't raise the worker count, which made tests flaky under CPU load locally. There are no retries anywhere (`retries: 0`): a test that fails once fails CI, and its trace (`retain-on-failure`) is in the uploaded report. Fix a flaky test's wait instead of adding retries back.
- To actually see a change: `npm run dev`, then drive it with Playwright (`playwright-core` comes with the `@playwright/test` devDependency) — most pages require an authenticated user. Fastest path: register a throwaway account via `/register` (no email verification), then navigate. Movie ID `550` (Fight Club) is a reliable TMDB id for detail-page checks.
- Write any verification scripts into the project root as `verify_*.js` (or `verify_*.py` for E2E/Playwright debugging; a throwaway Playwright spec that needs the e2e fixtures goes in `e2e/verify_*.ts`) and delete them before finishing — don't leave scratch scripts in the tree (`.gitignore` also excludes both patterns as a backstop).
- `useLocalStorage` (`src/hooks/useLocalStorage.ts`) `JSON.parse`s whatever it reads back out of a key, so a script/console write must be JSON-encoded (`localStorage.setItem("cinedb_theme", JSON.stringify("light"))`) — writing the bare string (`"light"` unquoted) makes the parse throw and silently falls back to the hook's default, with no visible error. Bit a Playwright screenshot script that tried to force light theme this way; theme never actually changed until the write was JSON-encoded.
- When scripting a page that renders `SkeletonCard` (`src/components/SkeletonCard.tsx`, antd `Skeleton`/`Skeleton.Image`) while its own data fetch is in flight, don't wait on `<img>` completeness alone before screenshotting/asserting — the real `<img>` tags for its cards don't exist in the DOM yet, so that wait trivially passes on the loading state itself. Wait for `.ant-skeleton` to be gone first, then wait on images.
- `e2e/python/pytest.ini` sets `timeout_method = thread`, not pytest-timeout's default `signal` — required for this suite specifically. A hung Playwright sync-API call blocks in a background thread (its own asyncio subprocess reaper), and `signal`-mode timeouts only interrupt the main thread, so they can't unblock it; the process then rides GitHub Actions' 6h default job timeout instead of failing the one test. `thread` mode force-exits the interpreter on timeout instead, which is Playwright's own documented recommendation. Don't revert this to `signal` even though it means a genuinely stuck test kills the whole run rather than just failing — that's the safer failure mode here. `.github/workflows/ci.yml`'s `e2e-python` job also caps at `timeout-minutes: 15` as a backstop. It runs with `--tracing=retain-on-failure --output=e2e/python/test-results` and uploads that folder only on failure (7 days), like `e2e-ts`'s report.
- **E2E fixtures and the strict catch-all**: TS specs import `test`/`expect` from `e2e/fixtures.ts`, not `@playwright/test`. Python tests use the `authed_page` fixture (`e2e/python/conftest.py`). Both register a catch-all for `**/api/**` first. An app API call no test mock handles gets a 501 and **fails the test at teardown, listing the URL**. An unmocked `/api/tmdb/**` call gets an empty results page instead (decorative hero/provider fetches). So when a new page or endpoint makes a test fail with "Unmocked app API calls", add the mock. Don't loosen the catch-all. Calls every authenticated page makes (library loads, followed people, notifications poll, mark-seen) live once in `mockAuthedBase`/`mockAppApi` (TS) and `mock_base_django_routes` (Python). A new app-wide call goes there, or every authenticated test fails. List endpoints must be mocked with `paginated([...])`, the real DRF shape, never a bare `[]` (`fetchAllPages()` accepts both, so a bare array hides shape bugs). Python's `fulfill_json` records a bare list sent to a list endpoint and fails the test at teardown. Mock records use the API's own field names. `backend/userdata/tests/test_e2e_mock_shapes.py` `ast`-reads the Python `MOCK_*` dicts (keep them plain literals) and compares them with the serializers and a real `/api/stats/` response. TS mocks use `satisfies` with the app's types (`AuthUser`, `*DTO` in `src/types/domain.ts`; TMDB-shaped literals with the `TMDB*` types), and the same test regex-reads those DTO interfaces and compares their fields with the serializers both ways, so a serializer field change needs the DTO updated too. Keep each DTO a plain `export interface XDTO { field: type; }` block it can parse. Never guard an assertion with `if locator.count() > 0:` (it doesn't wait, so the check silently skips), and don't sleep before asserting: wait for a positive anchor (the empty-state text, the error UI) before asserting absence or zero. Route patterns need a trailing `**` because `fetchAllPages()` always appends `?page=N`. Playwright checks routes last-registered-first, so a test's own `page.route()` overrides the base mocks and the catch-all. When one test needs different responses on the *same* pattern (GET the list vs POST to create), branch on `r.request.method` inside a single handler instead of stacking two routes (see `test_lists.py`'s `test_create_list_success_shows_new_card`).

## Don't
- Don't inline new "why we did it this way" design-rationale writeups back into `README.md`'s Architecture Overview — that's what `docs/ARCHITECTURE.md` is for (the ~55-bullet "Key design decisions" list used to live in the README until it was moved out for length; README now just links to it). Add new rationale bullets to `docs/ARCHITECTURE.md`, keep README to structure/diagram/feature-level docs.
- Don't bypass `docker-entrypoint.sh` / `backend/start.py` migration flow — `makemigrations` is intentionally not run automatically at boot; generate migrations explicitly.
- Don't add a new localStorage-backed data store — all user data (watchlist/watched/ratings/lists/etc.) lives in PostgreSQL via the Django API.
- Don't add `overflow-x: hidden` (or any non-`visible` overflow value) to `body`/`#root`/any ancestor of `.app-sidebar` without also setting `overflow-y` explicitly — an unpaired `overflow-x` silently promotes `overflow-y` to `auto` too (CSS spec), which turns that ancestor into an unintended scroll container and breaks the sidebar's `position: sticky` (it sticks relative to the nearest scrolling ancestor, not necessarily the viewport). `src/index.css` scopes it to `html` only for this reason.
- Don't let a new dropdown/popover/tooltip anchored inside the sidebar default to antd's `document.body` popup container — set `getPopupContainer` to mount it inside the sticky sidebar instead (see `SearchBox.tsx`), otherwise its scroll-linked reposition logic (built for triggers that scroll with the page) glitches against a trigger that doesn't.
