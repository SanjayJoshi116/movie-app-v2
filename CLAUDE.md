# CLAUDE.md

Guidance for Claude Code when working in this repo. See `README.md` for feature/architecture docs and `docs/ARCHITECTURE.md` for detailed design-decision rationale (auth, pagination, responsive breakpoints, recommendations caching, etc.) — this file covers conventions not obvious from reading the code once. Known open bugs live in `docs/BUG_BACKLOG.md`, grouped into planned OpenSpec changes. Check it before re-auditing, and keep its status table current when a change is proposed or archived.

## Stack
- Frontend: React 18 + TypeScript (strict) + Ant Design 5, CRA (`react-scripts`), React Router v6, Framer Motion, Recharts. Node 22 (`.nvmrc`, `engines`), the same as CI and `Dockerfile.frontend`. A newer local Node only warns (no `engine-strict`).
- Backend: Django 5.2 LTS + DRF + PostgreSQL, JWT auth (`djangorestframework-simplejwt`).
- `npm run dev` starts both: React dev server (3000), Django (8000). Django runs via the Anaconda env: `G:/Anaconda/envs/django/python.exe` (see `package.json` scripts) — use that interpreter for any manual `manage.py` command, not system Python. Base Anaconda has Django 6.0, which is how some migrations got "Generated by Django 6.0" headers. Backend deps are pinned (`backend/requirements.txt` direct, generated `backend/constraints.txt` transitive; Docker and CI install with `-c constraints.txt`), and `userdata/tests/test_dependency_versions.py` fails the suite if the installed Django's major.minor doesn't match the pin. `predev`/`prestart` run `kill-port 3000 8000` first so a stale process from a previous run doesn't silently block startup. `backend/start.py`'s pre-startup steps run in order — DB create → migrate → `createcachetable` (throttle counters' `DatabaseCache` table; no-op under DEBUG's LocMem) → best-effort `compute_recommendations` (capped at 30s, `subprocess.TimeoutExpired` caught and skipped) → `runserver`. That timeout matters: without it, a slow/hung TMDB call during the cache-warm step blocks `runserver` from ever starting, and `npm run dev` just never finishes booting Django with no error surfaced.
- TMDB requests are proxied by Django itself (`backend/userdata/tmdb_proxy_views.py`'s `tmdb_proxy`, mounted at `api/tmdb/<path:tmdb_path>`, `AllowAny` since it's public data) — there is no separate Node/Express layer (removed in 0.15.4). It uses a shared module-level `requests.Session()` with retry/pooling (`HTTPAdapter`+`Retry`), not a bare per-call `requests.get()` — a movie/TV detail page fires ~6 concurrent proxy calls, and a fresh-handshake-per-call approach saw sporadic transient 502s under that burst. Its timeout/retry values (`CONNECT_TIMEOUT`, `READ_TIMEOUT`, `RETRY`) are a time budget: `test_tmdb_proxy` asserts the computed `WORST_CASE_SECONDS` stays 5s under the `gunicorn --timeout` in `docker-entrypoint.sh`. Retune them freely, but never past that, or a slow TMDB gets sync workers killed instead of a clean 502. The frontend TMDB client (`src/api/tmdb.ts`) sends the user's JWT so `TmdbProxyThrottle` keys per user, not per NAT'd IP. On a 401 (an expired token on this `AllowAny` view) it retries once without the token, and it never logs out or refreshes: refresh stays only in `userApi`. Detail/person pages read `:id` only through `useValidId()` (`src/hooks/useValidId.ts`), because a decoded `..%2F` id would turn a proxy path into a request to another app endpoint, token included. Any new page that builds a proxy path from a route param must do the same. The notifications poll has the same kind of budget: `NOTIFICATIONS_BUDGET_SECONDS` (with `NOTIFICATIONS_MAX_FETCH` people per poll), pinned by `test_notifications` at ≤ that `--timeout` − 10.

- **Docker production stack**: the backend container runs as non-root `app` (uid 10001) with `/app` read-only to it. Only `/app/media` (the `media_data` volume) is writable, so anything that writes elsewhere at runtime fails in Docker but works under `npm run dev`. It applies only the migrations baked into the image (no host bind mount, no `--run-syncdb`). Security headers, including the enforced Content-Security-Policy, live in `nginx.conf`, not Django. A new external origin (image host, embed, font, API) must be added to that CSP or browsers block it in production while dev (no CSP) keeps working. `Dockerfile.frontend`'s `INLINE_RUNTIME_CHUNK=false` is what lets `script-src 'self'` work without an inline exception, so don't remove it (CI's build sets it too). `nginx.conf` serves `/static/` with `try_files $uri =404` (a missing old chunk is a 404, not `index.html`) and sends `Cache-Control: no-cache` for `index.html` through a `map` + server-level `add_header`. Never put an `add_header` inside a `location`: it drops every inherited security header there (`test_nginx_conf.py` fails on it). The db password lives only in `.env.db` (`POSTGRES_PASSWORD`, which the db container reads alone and `settings.py` falls back to), never in `.env.docker`. `TRUSTED_PROXY_COUNT` defaults to 1 and can be overridden from the shell or root `.env`. With `DEBUG` off the API renders JSON only (no browsable API).

## Conventions to reuse, don't reinvent
- **Font size**: never hardcode `fontSize: N`. Import `FONT_SIZE` from `src/constants/typography.ts` (`caption` 12 / `body` 14 / `emphasis` 16 / `display` 28). Icon-scaling `fontSize` props (antd icons) are the one exception — those stay numeric.
- **Info tooltips**: use `<InfoTooltip title="..." />` from `src/components/InfoTooltip.tsx` (wraps antd `Tooltip` + `InfoCircleOutlined`) next to any label/stat that needs a one-line explanation. Don't hand-roll a new `Tooltip`+icon pairing.
- **Dates**: render with `formatDateDMY()` from `src/utils/formatDate.ts` — fixed `dd-mm-yyyy`, not locale-dependent `toLocaleDateString()`.
- **Whose day is it** (`user-local-dates`): two rules.
  - **"Today"** is the requesting device's time zone. `userApi`'s interceptor sends it as `X-Timezone`, and the backend reads it only through `backend/userdata/timezones.py` (`request_tz`, `local_today`).
  - **A past watch's day** is the zone it was logged in: `WatchedEntry.watched_tz`, read through `entry_day` / `entry_local`. Blank (pre-change or imported without a zone) falls back to the device's zone.
  - **Never derive a user-facing day from a UTC instant:** no `toISOString().slice(0, 10)` (use `localISODate`), and no `.date()` / `strftime` on `watched_at` (use the helpers). On the frontend, show a watch's date with `formatWatchedDate(iso, watchedTz)`, which adds the zone label only when the offset differs from the device's.
  - **Bad zones fall back to UTC, never 400/500.** Unknown names are stored blank.
  - **CORS:** `X-Timezone` is in `CORS_ALLOW_HEADERS` because dev is cross-origin. Any new custom request header needs the same.
  - **Aliases:** Chromium reports some zones under old ICU aliases (`Asia/Calcutta` for `Asia/Kolkata`). Compare offsets, never names.
- **Fonts**: Poppins is set once via `commonTokens.fontFamily` in `src/theme/antdTheme.ts`. Never add a per-component `fontFamily` override.
- **Detail-page sections**: `MovieDetails.tsx` and `TVShowDetails.tsx` share `SectionHeader` (section divider+title), `WatchProviders` (streaming/rent logos), `MediaCardGrid` (poster-card grid for recommendations/similar/credits, default `limit=20`, optional `title`/per-item `subtitle`), and `ReviewsSection` (2-column review cards) from `src/components/`. Both pages render sections in the same order (Where to Watch → Cast → Recommendations → Similar → Trailers → Images → Reviews). Don't re-inline a copy in one of the two detail components — fix/extend the shared one. `PersonPage.tsx` also reuses `MediaCardGrid` (uncapped, `limit={array.length}`) for its Movies/TV credit tabs instead of a local card component. Both Recommendations and Similar are additionally run through `filterByGenreOverlap()` (`src/utils/filterByGenreOverlap.ts`) before being handed to `MediaCardGrid` — keeps only items sharing ≥half the opened title's genres, falls back to the unfiltered list rather than showing nothing. Reuse this util for any new genre-filtered grid instead of writing another overlap check.
- **Nav icon tooltips**: `Sidebar.tsx` and `BottomNav.tsx` both use `useFlashTooltip()` (`src/hooks/useFlashTooltip.ts`) to force-show a nav icon's `Tooltip` for ~1.4s right after it's clicked (`open={flashKey === key || undefined}`), since the tablet icon-rail and phone bottom-nav have no visible text label to confirm the destination. Reuse this hook for any new icon-only nav control instead of a bespoke timeout/state pair.
- **Library item cards**: `WatchlistPage.tsx`, `WatchedPage.tsx`, and `ListDetailPage.tsx` share `LibraryItemCard.tsx` (poster + `Card.Meta` + icon action buttons) for their item grids. `PeoplePage.tsx`, `SearchPage.tsx`'s People tab and `FollowingPage.tsx` share `PersonCard.tsx`. Don't hand-roll another `Card`/`Row`/`Col` poster grid — extend one of these. `LibraryItemCard.tsx`'s outer `motion.div` needs `height: "100%"` for cards in the same grid row to render equal height (antd's `Col` stretches to the row's tallest sibling by default, but only the wrapper explicitly filling that height makes the visible card box follow) — don't drop it when touching this component.
- **Cards that open a page are `CardLink`s**: any poster card/thumbnail that navigates to a detail or person page goes through `CardLink` (`src/components/CardLink.tsx`), a real router `<Link>` with an `href`, so Tab/Enter, Ctrl/middle-click new tab and the focus outline (`.card-link:focus-visible`, light/dark pair in `App.css`) all work. Never use a clickable `div`/`Card` `onClick` for this. When the target needs click-time router state (scroll position, `stashReturnState()`), pass `onNavigate` and keep `to` as the real href. A plain click or Enter calls `onNavigate`, and modifier clicks open `to` natively. Whole card = link only when the card has no buttons of its own (`MediaCardGrid`, cast, Calendar, Home strip). If it has buttons (`PersonCard` Follow, `LibraryItemCard` actions), only the poster is the link, because a button nested in a link is invalid. `PersonCard` also passes `stopPropagation`, because its card-level mouse `onClick` stays. `LibraryItemCard` needs a `to` prop from its callers. There are no exceptions left: Search's result cards, the Recommendations/Following `SectionRow` cards and the Lists page cards were converted in `surface-failures-2` (poster-only links, since those cards have buttons).
- **Watched status source of truth**: there is exactly one "is this watched" boolean per title — the shared `WatchedContext` (`isWatched(id, type)` / `toggleWatched(...)`). `WatchlistEntry` has no `watched` column; don't add one back or otherwise let a page maintain its own separate watched flag — it will drift out of sync with whatever else marks/unmarks the same title.
- **Shared UI constants**: `IMG_URL`, `POSTER_THUMB_URL` (`w185`, small poster thumbnails e.g. HomePage's recently-watched strip), `STILL_URL` (`w300`, episode stills), `LOGO_URL` (`w92`, provider logos), `BACKDROP_URL`, `RATING_GOLD`, `WATCHED_GREEN`, `RATING_WARN`, `RATING_BAD` live in `src/constants/ui.ts`; provider deep-links (`PROVIDER_SEARCH_URLS`) live in `src/constants/providers.ts`. Color *rules* live in `src/utils/colors.ts`: `ratingColor(vote)` (TMDB score tag: ≥8 green, ≥5 amber, else red) and `avatarColor(username)` (stable fallback avatar background) — import these instead of writing another local `getRatingColor`/palette hash (there were 5 and 2 copies until `frontend-polish`). Don't hardcode hex colors or TMDB image URLs inline — for one-off section-header/divider colors, and for any text/fill/tooltip that must read in both themes (Stats' labels, heatmap and chart tooltips), use antd's `theme.useToken()` (e.g. `colorTextSecondary`, `colorTextTertiary`, `colorFillTertiary`, `colorBgElevated`, `colorBorderSecondary`) over a literal hex or `rgba(255,255,255,…)`, per `ProfileModal.tsx`/`StatsPage.tsx`.
- **No-poster fallback**: use `<PosterPlaceholder className="..." style={{...}} />` (`src/components/PosterPlaceholder.tsx`) wherever a poster/profile image might be missing — pass the same className the real `<img>` would use (`movie-poster-img`, `rec-card-img`, `cast-card-img-lg`, `detail-poster-img`) so it picks up the same aspect-ratio/border-radius. It's a real DOM element (renders "No Image" text that inherits the app's Poppins font), not an image — don't reintroduce an SVG-data-URI placeholder (`NO_IMAGE` was removed for exactly this reason: text baked into an `<img src="data:...">` SVG can't see the page's `@font-face`, so it could never match the rest of the UI's font). Two call sites (`PersonPage.tsx`, `StatsPage.tsx`) pass an extra `style={{ aspectRatio: "2 / 3" }}` since their real-`<img>` counterpart has no CSS class enforcing one — check whether yours needs the same before assuming the className alone sizes it. `Movie.tsx`, `TVShowCard.tsx`, `RecommendationsPage.tsx`, and `SearchPage.tsx`'s Movies/TV tabs were all still falling back to a `placehold.co` SVG `<img>` instead of this component until 0.15.7 — check for that pattern (`poster_path ? <img.../> : "https://placehold.co/..."`) before assuming every card grid already follows the convention.
- **Light/dark theme parity**: `src/theme/antdTheme.ts`'s `darkThemeConfig` and `lightThemeConfig` should carry the same token set (`colorText`, `colorTextSecondary`, `colorBorder`, `colorBorderSecondary`, `colorBgElevated`, plus `Table`/`Drawer` component overrides) — light mode used to only override 3 background tokens and fell back to stock antd gray for everything else, which is why it looked unfinished next to dark mode's bespoke "cinema-dark" palette until this was fixed. If you add a new token/component override to one theme, add the equivalent to the other. Same for `App.css`'s `body.dark-theme`/`body:not(.dark-theme)` scoped rules (`.app-content` gradient, `.glass-sidebar`, `.glass-overlay-card`, `.app-bottom-nav`, `::-webkit-scrollbar-*`) — every rule scoped to one theme needs its sibling, per the scrollbar bug this fixed (it was unscoped entirely, so it stayed dark-navy even in light mode).
- **Avatar URLs**: a user's `avatar_url` (from `AuthContext`'s `user` object) is a relative Django media path — always resolve it through `resolveAvatarUrl()` from `src/constants/media.ts` before passing to an `<Avatar src=... />`; never concatenate `REACT_APP_API_BASE_URL`/TMDB constants with it. Uploading/removing a photo goes through `uploadAvatar()`/`removeAvatar()` (`src/api/userApi.ts`) then `setUserData()` (`AuthContext`) to push the returned user into context/localStorage — the same helper `updateProfile()` uses internally, so don't duplicate the persist-to-localStorage logic inline.
- **List-page filter bars**: three layers, not one. Chrome (`FilterBar`, `src/components/FilterBar.tsx`) renders the search `Input`/sort `Select`/type-filter `Select`/"Clear filters" `Button` and is used by all 6 list/browse pages (`WatchlistPage`, `WatchedPage`, `ListDetailPage`, `ListsPage`, `FollowingPage`, `RecommendationsPage`) — always build a new list-page filter bar on this, never hand-roll the `<Space>` markup again. State (`useLibraryFilters`, `src/hooks/useLibraryFilters.ts`) owns search/sort/type-filter state + sessionStorage persistence + the filter-then-sort pipeline; `WatchlistPage`, `WatchedPage`, `ListsPage`, `FollowingPage`, and `ListDetailPage` are all on it now. `keyPrefix` must stay each page's pre-existing sessionStorage key prefix; `getTitle`/`getType` are optional accessors (default to reading `.title`/`.type` directly) for items like `List`/`Person` that carry the same fields under different names or lack a movie/tv distinction entirely — omit `getType` and its type-filter becomes a no-op, don't add a redundant enable flag. An optional `extraFilter` predicate lets a page layer one more filter on top (Watchlist's watched-status filter) without forking the hook. Grid (`MediaGrid`, `src/components/MediaGrid.tsx`) renders the poster-card `Row`/`Col`; `WatchlistPage`/`WatchedPage` use its default `colSpan` (`{xs:12, sm:8, md:6, lg:4}`), `ListDetailPage` overrides `colSpan={{ md: 4 }}` to keep its existing 6-cards-per-tablet-row density — check an override is still needed before assuming every `MediaGrid` caller wants the default. `RecommendationsPage.tsx` stays off `useLibraryFilters`/`MediaGrid` permanently, not as a pending migration: it filters across grouped sections (`toFilteredSections` maps a predicate over three separate arrays) rather than one flat list, and has no sort control at all — a structural mismatch, not a naming one, so don't try to force it onto either shared piece.
- **Adult content toggle**: single switch lives in `src/components/layout/FilterPanel.tsx`, bound to the shared `includeAdult`/`setIncludeAdult` from `useAppContext()`/`UIContext`. Don't add another copy elsewhere (e.g. back into `SearchBox.tsx`) — every search/discover call already reads this one context value.
- **Browse filters and Back restore** (`src/utils/browseFilters.ts`, `src/utils/browseReturnState.ts`): genre chips come from `movieGenres`/`tvGenres` by media type, and a page sends genres only through `genresFor(mediaType, ids)`. Decide "use discover vs the category" only with `hasActiveFilters()`, and send `with_genres` only to discover (category endpoints ignore it). Applied filters reset per browse scope inside `App.tsx`'s render, so don't move that reset into an effect. Any new browse → detail navigation calls `stashReturnState({...restore, isReturn: true})` before `navigate()`, so browser Back restores like the in-app Back button. See `docs/ARCHITECTURE.md` for why it's a raw `replaceState`.
- **Add to List**: use `<AddToListModal open onClose mediaId mediaType title posterPath voteAverage />` (`src/components/AddToListModal.tsx`) — don't re-inline another bare-checkbox list picker. It already handles search, inline create-new-list, and the add/remove toggle itself.
- **Mark as Watched**: use `<MarkWatchedModal open mediaId mediaType onCancel onConfirm />` (`src/components/MarkWatchedModal.tsx`) whenever a UI lets the user mark something watched — it self-fetches runtime + streaming-platform options from TMDB given just the id/type, so callers never pass detail data in. Only wire it for the "mark as watched" direction; unmarking stays an instant `toggleWatched(...)` call, no modal. If you add a new watched-toggle icon anywhere, route it through this modal — several existing ones (`Movie.tsx`, `TVShowCard.tsx`, `RecommendationsPage.tsx`, `SearchPage.tsx`, `WatchlistPage.tsx`) were missed on a first pass and silently never recorded runtime/platform until fixed.
- **Search inputs**: every page-level search/filter `Input`/`Input.Search` needs explicit `id`, `name`, and `autoComplete="off"` — Chrome DevTools flags free-text inputs missing these. Follow the existing ones (`WatchlistPage.tsx`, `WatchedPage.tsx`, `PeoplePage.tsx`, `SearchBox.tsx`, etc.) for naming (`"<page>-search"`).
- **Load and write feedback** (`surface-failures`): every load renders loading → `<LoadError onRetry />` (`src/components/LoadError.tsx`, `notFound` variant for 404s) → empty CTA → content. Never let a failed fetch fall through to the empty state. Library hooks expose `error` and start `isLoading` at `isAuthenticated`, so branch on both. A write shows success only after `await` resolves, so use `try { await x(); showSuccess() } catch (err) { showError(getApiError(err, ...)) }`, never fire-and-forget plus toast. Context mutation types return `Promise`, so a missing `await` at least reads as wrong. Per-item double-click protection lives in the hooks via `createInflight()` (`src/utils/inflight.ts`); give any new mutation hook the same per-item slot instead of disabling buttons per call site. Inside one hook, guarded wrappers must call the unguarded inner functions, or `toggle` deadlocks on its own slot. `useToast` is memoized and dedupes identical messages by `key`, so don't wrap it again. Error text comes only from `getApiError(err, fallback)` (`src/utils/apiError.ts`): a non-axios error or a non-object body (an nginx 502 page, Django's HTML 500) gives the call site's `fallback`, and no response at all gives `CONNECTION_ERROR`. Never show `err.message` or read `response.data` yourself. Form submits (register, create/edit list) show `loading`/`confirmLoading` and dedupe in the hook (`surface-failures-2`). A view whose input can change mid-request (a filter, a media type) drops superseded responses with a request id or a `cancelled` flag, as `CalendarPage`/`HeroBanner` do.
- **Followed people / notifications are shared providers**: read follow state only through `useFollowedPeople()` (a reader for `FollowedPeopleProvider`, which fetches lazily on first use, so don't make it eager or every e2e base fixture needs a new mock). Read notifications only through `useNotifications()` (a reader for `NotificationsProvider`; one poller for both bells). Both providers are mounted in `index.tsx`. A test that renders a consumer needs the provider. A failed followed-people load sets `error` (keeping the previous list) and offers `retry()`. FollowingPage shows `LoadError`, and `PersonCard` disables Follow while `error` is set, because "Follow" would claim "not following".
- **Login/register API calls**: use `publicApi` from `src/api/userApi.ts`, not the default `userApi` export. `userApi` carries a 401-refresh interceptor that, on a failed login, finds no refresh token yet and hard-redirects to `/login` — before the page's own error handling can show a message. `publicApi` is the same base client with no interceptors, meant exactly for login/register/password-reset.
- **Session teardown and unmount-time caches**: every logout path goes through `clearSession()` (`src/api/userApi.ts`), and must call it *before* clearing auth state (`setUser(null)`, redirect). Any page that saves a cache in a `useEffect` cleanup must write via `saveSessionCache()`, not `sessionStorage.setItem`. Logout unmounts the page after teardown, so a plain write puts the previous user's data back for the next account in the tab (`RecommendationsPage`/`SearchPage` did exactly this until `fix-session-followups`). Change-triggered writes (`useLibraryFilters`-style effects) don't need it. Token-refresh logic lives only in the `userApi` interceptor (cross-tab `navigator.locks` + session-unchanged check); don't add a second refresh path. It calls `forceLogout()` only when the refresh endpoint rejects the token (`400`/`401`). A 429/5xx/network failure fails the request and keeps the session. Each tab is bound to the account it shows: `AuthProvider` must route every user change through its `setUser` wrapper (which calls `bindSessionUser`), and the interceptor refuses requests while the stored user differs. Its `storage` listener reloads the tab when another tab signs in as a different account (see `docs/ARCHITECTURE.md`).
- **Failed-login UX** (`LoginPage.tsx`): on error, keep the username field filled (only clear+refocus password) instead of `form.resetFields()` — don't make the user retype a correctly-entered username after one bad password attempt. Branch the message on `err.response?.status`: 400/401 → "Invalid username or password.", 429 → the "too many login attempts" message (`LoginThrottle`, required by the `login-page` spec), anything else (network error, 5xx, timeout) → "Can't reach the server. Check your connection and try again." — don't collapse these into one generic message, they're different failure modes the user needs to distinguish.
- **Responsive breakpoints**: three CSS-only tiers, no JS width checks (`Grid.useBreakpoint()`, `window.innerWidth`, etc.) anywhere in the app — keep it that way. `<768px` phone (`Sidebar` hidden, `BottomNav` shown), `768-991px` tablet (`Sidebar` collapses to a 64px icon rail via `App.css`'s `@media (min-width: 768px) and (max-width: 991px)` block), `≥992px` desktop (full 220px sidebar, the unqualified default). New fixed-width elements (modals, cards, filter inputs) should use `width: "100%", maxWidth: N` instead of a bare `width: N`, per the auth-page `Card`s and list-page filter bars — a bare fixed px width is exactly the pattern that overflows on phones under that width.
- **Sidebar manual collapse (desktop only)**: `Sidebar.tsx` also lets the user fold the full 220px sidebar down to the same 64px icon rail tablet gets automatically, via a footer toggle button. State is `collapsed` (`useLocalStorage<boolean>("cinedb_sidebar_collapsed", false)`, same hook/key-prefix convention as `cinedb_theme`), applied as a `.sidebar-collapsed` class on `.app-sidebar`. The collapsed-state rules live in `App.css`'s `@media (min-width: 992px)` block and intentionally re-target the same child selectors (`.sidebar-logo-full`, `.sidebar-label`, `.ant-menu-item` padding, etc.) as the tablet rail — don't fork a second set of rules. The toggle button itself (`.sidebar-collapse-toggle`) is hidden below 992px since tablet/phone already have their own fixed layout.
- **Sidebar vertical space budget**: `.app-sidebar` is `height: 100vh; overflow-y: auto` — a deliberate safety valve, not a bug — but it's already flush with zero slack at a standard 1366×768 viewport. `Sidebar.tsx` renders one extra element (the filter-toggle button) only when `isBrowsePage` (`/movies`, `/tv`, `/anime`), so those three routes have less headroom than every other page. Don't add new always-or-conditionally-rendered elements to the sidebar (logo, search, menu, footer) without checking `scrollHeight` vs `clientHeight` at 1366×768 first — it doesn't take much to tip it into showing its own scrollbar. `NotificationBell.tsx` follows this: it's rendered inline inside the existing theme/collapse-toggle footer row, not as a new stacked row — do the same for any future icon-only nav addition. In the 64px rail (tablet, or desktop collapsed) that row can't fit side by side, so `App.css` turns `.sidebar-footer` into a 2-column, 30px-cell icon grid (`.sidebar-footer-icons` is `display: contents`, so the browse-page Filters button shares it). A new footer icon therefore costs a grid cell, and possibly a new row, at 1366×768. Keep footer layout in `App.css` classes, not inline `style`, because inline styles beat the rail overrides. `NotificationBell` takes its `placement` from the host (`Sidebar`: `topLeft` with `autoAdjustOverflow={false}`, since antd measures overflow against the 64px sidebar and flips the popup off-screen; `BottomNav`: `top`). `e2e/responsive.spec.ts` checks the popup box at every tier. Phones open browse filters from `BottomNav`'s Filters button (browse pages only), which shares `App.tsx`'s `showFilterPanel` state with the sidebar's button. Pass both the same props, and don't add a third trigger.
- **`usePaginatedFetch`'s `restoredState` param and its StrictMode trap**: the hook (`src/hooks/usePaginatedFetch.ts`) supports two restore modes — refetch `restore.savedLoadedPages` pages over the network (Home/Anime/People, restore info comes from router `location.state`), or seed `items`/`hasMore` directly via `restoredState` with zero network calls (Search, which caches full result arrays in sessionStorage itself). Its mount effect guards against React 18 StrictMode's dev-only double-invoke. A *real* rerun only ever happens when `fetchPage`'s identity (or `retryToken`) changes, so a replay with an identical pair is ignored. The guard (`inflightRef`) is armed when a load *starts*, not when it finishes: the replay arrives synchronously while the first load is still in flight, so it revives that load (whose cleanup had just cancelled it) instead of starting a second one. It was originally armed in `finally`, which meant every first load and every Back-restore fetched each page twice under `npm run dev` until `ci-coverage`. StrictMode tests in `usePaginatedFetch.test.tsx` pin this. Don't remove that guard: without it, the dev-only replay silently re-fetches and clobbers a correctly-restored multi-page/scroll state down to a fresh page 1 (only reproduces under `npm run dev`'s StrictMode, invisible in production builds — found via the app's own documented Playwright verification method, not by reading the code). Relatedly: any `fetchPage`/similar callback passed into this hook must not depend on a non-memoized inline closure (e.g. a `fetcher` prop recreated every render) in its own `useCallback` deps — that reintroduces an infinite refetch loop (`SearchPage.tsx`'s `usePaginatedSearch` hit this; fixed by reading the closure through a ref instead).
- **Per-endpoint throttle scopes**: `LoginThrottle`/`RegisterThrottle`/`PasswordResetThrottle` (`auth_views.py`) established the pattern — subclass `AnonRateThrottle` (or `UserRateThrottle`, for endpoints authenticated users hit too) with a `scope` attribute, register the rate in `settings.py`'s `REST_FRAMEWORK.DEFAULT_THROTTLE_RATES`, apply via `@throttle_classes([...])`. `TmdbProxyThrottle` (`tmdb_proxy_views.py`, `120/min`) and `NotificationsThrottle` (`notifications_views.py`, `30/min`) extend this to the two TMDB-cost endpoints — use `UserRateThrottle` as the base for anything `AllowAny`-or-authenticated that costs real TMDB quota per call, not `AnonRateThrottle` (which no-ops entirely for authenticated requests, per DRF's own `get_cache_key`). The exception is `TokenSessionThrottle` (`auth_views.py`, `token_refresh: 60/min`) on token refresh and logout. Those views authenticate nobody (`authentication_classes=()`), so it's anon-based, and it *replaces* the default throttles there. Don't put them back on the shared `anon: 300/day` bucket, because users behind one NAT ran it dry and got logged out.
- **Bare `except Exception:` convention**: narrow to what the try block can actually raise — `(requests.RequestException, ValueError)` for a TMDB fetch alone, add `KeyError`/`TypeError` if the code does direct dict indexing (`c["id"]`) instead of `.get()`, add `django.db.Error` if a DB write follows. A handful of sites are legitimately broad on purpose (`recommendations.py`'s `_refresh_cache` and the `f.result()` loop in `_compute_personalized`, `compute_recommendations.py`'s per-user batch loop, `auth_views.py`'s `send_mail` call) — each has a comment explaining why (heterogeneous TMDB+numpy/sklearn+DB operation mix in a background/batch context, or a mail backend whose exception type varies by deploy). Match that judgment for new code — reflexive bare-except is the default to avoid, not broad-catch itself.
- **Upstream failures and worker threads (backend)**: never write a placeholder (empty genres, empty credits) when a TMDB call fails. Keep the existing value, or store nothing so the next call retries (`_store_media_cache`, `_fetch_followed_people_credits`). The same holds for a whole result: a recommendations refresh goes through `save_recommendations()`, which keeps the stored row when a TMDB call failed (marked on the shared `FetchHealth`) and the new result has fewer non-empty sections. A new except-branch in a compute that drops content must call `health.mark_failed()`. In a `ThreadPoolExecutor`, workers only do HTTP. DB queries and `django.core.cache` calls stay on the calling thread, because the production cache is DB-backed and each worker thread would otherwise open and leak its own connection. Watched-title metadata (genres, language, year) is filled only through `metadata_backfill.py` (`request_backfill` for fire-and-forget, `backfill_entries` when the caller needs the data), never by a new ad-hoc thread.
- **Recommendation refresh triggers**: schedule a background recompute only via `recommendations.request_refresh(user_id, rerun_if_running=...)` (or `_start_refresh_if_needed` from views), never by starting a thread directly. It coalesces per user (one running + at most one follow-up), and `signals.py` defers it with `transaction.on_commit`. A thread-per-trigger path is how clearing a 500-item watched history used to start 500 concurrent TMDB-heavy refreshes. Any new early-exit in the thread target must still call `_finish_refresh(user_id)`, or that user stays "pending" until the process restarts.
- **Serializer input bounds**: a hand-declared camelCase serializer field (`posterPath = CharField(source="poster_path")`) loses the model's `max_length`/`choices`/range, so restate them. Use `FiniteFloatField` for every float input, never plain `FloatField`: it accepts `"NaN"`, which makes every later read of that account 500. Use `MediaIdentityMixin` for any new `mediaId`/`mediaType` serializer, and `INT32_MAX` for id bounds. Endpoints that read the body directly go through a small input serializer, not `request.data.get(...)`, which 500s on a JSON array body.
- **Imports, backups and paginated lists**: new bulk endpoints go through `bulk_import()` (`backend/userdata/bulk_import.py`): create-only and all-or-nothing per request, with `bulkImport()` in `userApi.ts` chunking at 500. Read every CSV with `parseCSV`/`parseCSVForImport`/`parseBackupCSV` (`src/utils/csvParse.ts`), never a line split, because quoted fields contain newlines. Write every CSV through `buildCSVString` (`src/utils/export.ts`): its `escape()` prefixes a `'` to cells starting with `=` `+` `-` `@` tab CR (or `'`), so spreadsheets don't run them as formulas, and `parseCSV` strips exactly that one `'` back off. A new exporter or importer that bypasses either breaks the lossless round trip. Backup format changes stay additive in `src/utils/backup.ts`, so older backups keep importing. Any paginated `order_by` on a timestamp needs an `-id` tiebreaker: bulk imports create ties, and `fetchAllPages` then returns duplicates and skips rows.
- **Uploads are typed by content, not by name**: avatar files get their extension from PIL's decoded `Image.format` (`avatar_upload_path` whitelists `jpg`/`png`/`webp`), never from the client filename or declared content type. `/media/` is served with a content type guessed from the extension, so a client-chosen `.html` name was stored XSS on the app's own origin. Apply the same rule to any future upload.
- **Health endpoint stays unthrottled**: `health_views.health` has `@throttle_classes([])`. Compose polls it every 10s, so any throttle (even the anon default) eventually marks the container unhealthy. Don't remove it, and don't route new orchestrator probes through a throttled view.
- **Token refresh uses a custom view, not simplejwt's stock one**: `urls.py`'s `auth/token/refresh/` route is wired to `SafeTokenRefreshView` (`auth_views.py`), which wraps `TokenRefreshSerializer.validate()`'s unguarded `User.objects.get(...)` and converts a since-deleted token owner into a clean `InvalidToken` (401) instead of an unhandled 500. Don't swap this back to `rest_framework_simplejwt.views.TokenRefreshView` — that regresses a confirmed, reproduced bug (verified via a direct `APIRequestFactory` repro: delete a user, replay their still-unexpired refresh token, stock view 500s / this view 401s cleanly). Its serializer also enforces the `hash_password` claim (`CHECK_REVOKE_TOKEN`), which the stock one checks only on access tokens. That check is what stops a refresh racing a password change from surviving revocation (`test_password_bound_tokens.py`). Don't turn `CHECK_REVOKE_TOKEN` off, and issue tokens only through `RefreshToken.for_user()` (`_tokens_for_user`), which stamps the claim.
- **`ALLOWED_HOSTS` wildcards under `DEBUG`**: `settings.py` appends `"*"` to `ALLOWED_HOSTS` when `DEBUG` is true, mirroring `CORS_ALLOW_ALL_ORIGINS`. This matters because the frontend now calls Django directly (no Express layer in between since 0.15.4) — a LAN device hitting the dev server by IP (`192.168.x.x:8000`) sends that IP as its real Host header, and without the wildcard Django 400s with `DisallowedHost` before the view ever runs. Prod is fail-closed: `DEBUG` defaults to off when unset, and with it off `settings.py` raises `ImproperlyConfigured` on an empty or wildcard `ALLOWED_HOSTS` (so Docker/LAN hosts must be listed explicitly, including `localhost` for the compose healthcheck). `npm run dev` gets `DEBUG=True` from `start.py`'s `os.environ.setdefault`, and pytest gets it from `backend/pytest_dev_env.py` (loaded via `-p` in `pytest.ini`, because a root `conftest.py` runs after pytest-django has already imported settings) — don't move that default into `conftest.py`, and don't flip the settings default back to `True`.

## Verification
- Typecheck: `npm run typecheck` (app plus e2e specs via `e2e/tsconfig.json`; always run after TSX/TS edits). Lint: `npm run lint` (`--max-warnings=0`; CI fails on any warning). Backend CI also runs `ruff check backend/` and `makemigrations --check --dry-run`, so run both before pushing backend changes. ruff is pinned in `backend/requirements-test.txt` (and `constraints.txt`); bump the pin on purpose, in both files, since `test_dependency_versions.py` fails when the installed ruff differs.
- TS e2e: `npx playwright test`. `playwright.config.ts` starts only the CRA dev server (`npx react-scripts start`) because every spec mocks its API calls; locally it reuses a running `npm run dev`. CI runs it in the `e2e-ts` job (Node 22, both projects).
- To actually see a change: `npm run dev`, then drive it with Playwright (`playwright-core` is already a devDependency) — most pages require an authenticated user. Fastest path: register a throwaway account via `/register` (no email verification), then navigate. Movie ID `550` (Fight Club) is a reliable TMDB id for detail-page checks.
- Write any verification scripts into the project root as `verify_*.js` (or `verify_*.py` for E2E/Playwright debugging) and delete them before finishing — don't leave scratch scripts in the tree (`.gitignore` also excludes both patterns as a backstop).
- `useLocalStorage` (`src/hooks/useLocalStorage.ts`) `JSON.parse`s whatever it reads back out of a key, so a script/console write must be JSON-encoded (`localStorage.setItem("cinedb_theme", JSON.stringify("light"))`) — writing the bare string (`"light"` unquoted) makes the parse throw and silently falls back to the hook's default, with no visible error. Bit a Playwright screenshot script that tried to force light theme this way; theme never actually changed until the write was JSON-encoded.
- When scripting a page that renders `SkeletonCard` (`src/components/SkeletonCard.tsx`, antd `Skeleton`/`Skeleton.Image`) while its own data fetch is in flight, don't wait on `<img>` completeness alone before screenshotting/asserting — the real `<img>` tags for its cards don't exist in the DOM yet, so that wait trivially passes on the loading state itself. Wait for `.ant-skeleton` to be gone first, then wait on images.
- `e2e/python/pytest.ini` sets `timeout_method = thread`, not pytest-timeout's default `signal` — required for this suite specifically. A hung Playwright sync-API call blocks in a background thread (its own asyncio subprocess reaper), and `signal`-mode timeouts only interrupt the main thread, so they can't unblock it; the process then rides GitHub Actions' 6h default job timeout instead of failing the one test. `thread` mode force-exits the interpreter on timeout instead, which is Playwright's own documented recommendation. Don't revert this to `signal` even though it means a genuinely stuck test kills the whole run rather than just failing — that's the safer failure mode here. `.github/workflows/ci.yml`'s `e2e-python` job also caps at `timeout-minutes: 15` as a backstop.
- **E2E fixtures and the strict catch-all**: TS specs import `test`/`expect` from `e2e/fixtures.ts`, not `@playwright/test`. Python tests use the `authed_page` fixture (`e2e/python/conftest.py`). Both register a catch-all for `**/api/**` first. An app API call no test mock handles gets a 501 and **fails the test at teardown, listing the URL**. An unmocked `/api/tmdb/**` call gets an empty results page instead (decorative hero/provider fetches). So when a new page or endpoint makes a test fail with "Unmocked app API calls", add the mock. Don't loosen the catch-all. Calls every authenticated page makes (library loads, followed people, notifications poll, mark-seen) live once in `mockAuthedBase`/`mockAppApi` (TS) and `mock_base_django_routes` (Python). A new app-wide call goes there, or every authenticated test fails. List endpoints must be mocked with `paginated([...])`, the real DRF shape, never a bare `[]` (`fetchAllPages()` accepts both, so a bare array hides shape bugs). Python's `fulfill_json` records a bare list sent to a list endpoint and fails the test at teardown. Mock records use the API's own field names. `backend/userdata/tests/test_e2e_mock_shapes.py` `ast`-reads the Python `MOCK_*` dicts (keep them plain literals) and compares them with the serializers and a real `/api/stats/` response. TS mocks use `satisfies` with the app's types (`AuthUser`, `*DTO` in `src/types/domain.ts`). Never guard an assertion with `if locator.count() > 0:` (it doesn't wait, so the check silently skips), and don't sleep before asserting: wait for a positive anchor (the empty-state text, the error UI) before asserting absence or zero. Route patterns need a trailing `**` because `fetchAllPages()` always appends `?page=N`. Playwright checks routes last-registered-first, so a test's own `page.route()` overrides the base mocks and the catch-all. When one test needs different responses on the *same* pattern (GET the list vs POST to create), branch on `r.request.method` inside a single handler instead of stacking two routes (see `test_lists.py`'s `test_create_list_success_shows_new_card`).

## Don't
- Don't inline new "why we did it this way" design-rationale writeups back into `README.md`'s Architecture Overview — that's what `docs/ARCHITECTURE.md` is for (the ~55-bullet "Key design decisions" list used to live in the README until it was moved out for length; README now just links to it). Add new rationale bullets to `docs/ARCHITECTURE.md`, keep README to structure/diagram/feature-level docs.
- Don't bypass `docker-entrypoint.sh` / `backend/start.py` migration flow — `makemigrations` is intentionally not run automatically at boot; generate migrations explicitly.
- Don't add a new localStorage-backed data store — all user data (watchlist/watched/ratings/lists/etc.) lives in PostgreSQL via the Django API.
- Don't add `overflow-x: hidden` (or any non-`visible` overflow value) to `body`/`#root`/any ancestor of `.app-sidebar` without also setting `overflow-y` explicitly — an unpaired `overflow-x` silently promotes `overflow-y` to `auto` too (CSS spec), which turns that ancestor into an unintended scroll container and breaks the sidebar's `position: sticky` (it sticks relative to the nearest scrolling ancestor, not necessarily the viewport). `src/index.css` scopes it to `html` only for this reason.
- Don't let a new dropdown/popover/tooltip anchored inside the sidebar default to antd's `document.body` popup container — set `getPopupContainer` to mount it inside the sticky sidebar instead (see `SearchBox.tsx`), otherwise its scroll-linked reposition logic (built for triggers that scroll with the page) glitches against a trigger that doesn't.
